哈希能让数据留下固定长度的指纹。收到一个指纹时，还要问它来自哪里，是否有别人能替换它，以及它是否用于验证低熵口令。

## 哈希的三个安全属性（讲义第 1–15 页）

**哈希函数（Hash Function）** 接收任意长度的消息 M，输出固定长度的 **摘要（Message Digest）** `H(M)`。普通哈希没有秘密密钥。区分三种安全属性时，先看题目指定了什么。

| 已知或可选的输入 | 对应属性 |
| --- | --- |
| 给出摘要 y，要求找任何 x 使 `H(x) = y` | **原像抗性（Preimage Resistance）** |
| 给定消息 x，再找另一条消息与它同摘要 | **第二原像抗性（Second-Preimage Resistance / Weak Collision Resistance）** |
| 两条不同消息都可以选择，只要求摘要相同 | **碰撞抗性（Collision Resistance / Strong Collision Resistance）** |

**Merkle–Damgård 构造（Merkle–Damgård Construction）** 先填充消息，再逐块更新 **链式状态（Chaining State）**。SHA-256 的块长是 64 字节，填充包含一个起始 1 位、随后若干个 0 位，最后 8 字节记录原始比特长度。**MD5** 和 **SHA-1** 的碰撞抗性已经被攻破。**SHA-2** 与 **SHA-3** 是讲义中区分的后续家族，SHA-3 使用不同的构造。命令行、Python、SQL 等实现如果收到同一组字节，应算出相同摘要。末尾换行、字符编码和序列化都会改变输入。

## 生日界和长度扩展（讲义第 16–25 页）

**生日问题（Birthday Problem）** 考任意一对是否碰撞。理想 n 位哈希有 `N = 2^n` 种输出，k 个不同输入形成 `k(k−1)/2` 对。至少一次碰撞的概率近似 `1 − exp(−k(k−1)/(2N))`。所以随机碰撞约需 `2^(n/2)` 次试验的量级，匹配一个固定摘要平均约需 `2^n` 次。举例，理想的 32 位摘要约在 7.7 万个不同输入时达到 50% 碰撞概率。

当签名或文件识别只看摘要，碰撞可能让不同内容得到相同结果。可信的参考摘要可以发现下载差错，对可同时更换文件和摘要的场景则需要额外认证。

**长度扩展（Length Extension）** 源于部分迭代哈希会把末尾状态直接用作摘要。影响取决于算法及其输出方式，直接把密钥作为 SHA-256 输入前缀的自制方案，因此无法提供期望的消息认证。复习时把「状态可以继续」与「两份消息摘要碰巧一样」区分开。

## MAC 和 HMAC（讲义第 26–34 页）

**消息认证码（Message Authentication Code, MAC）** 用共享密钥为消息算一个 **标签（Tag）**。双方验证标签可以检查完整性和来源，消息本身仍可公开读出。

- **CBC-MAC** 像 CBC 一样逐块链接状态，最后输出一个标签。基础构造要约束消息长度，同一密钥直接混用不同长度会出现安全问题。讲义的变体用单独的最终加密处理标签。
- **HMAC（Hash-Based Message Authentication Code）** 先将密钥规整为哈希的块长度，用两种固定掩码分出内层和外层。公式为 `H((K' ⊕ opad) || H((K' ⊕ ipad) || M))`。`ipad`、`opad` 分别是每字节重复的 0x36、0x5c，`||` 表示拼接。外部看到的是外层结果，验证时还会重新计算密钥参与的内层摘要。

## 同时加密和认证（讲义第 35–41 页）

**认证加密（Authenticated Encryption, AE）** 同时给出保密性和完整性。**带附加数据的认证加密（Authenticated Encryption with Associated Data, AEAD）** 还能认证明文包头等字段。**伽罗瓦计数器模式（Galois/Counter Mode, GCM）** 用 CTR 加密，用 **GHASH** 参与算认证标签。**附加数据（Associated Data, AD / AAD）** 不经过加密，但变动会让标签检查失败。**GMAC** 是 GCM 体系下的认证用法。

实验中只改变密文、附加数据或标签的任意一项，就能看到验证失败。应用只应在验证通过后使用解密结果。同一密钥下按算法要求保持 nonce 唯一。

## 口令怎样存、怎样验证（讲义第 42–58 页）

Linux 的 `/etc/passwd` 放账号基本信息，通常把验证口令所需的数据留在访问受限的 `/etc/shadow`。**盐（Salt）** 是每个账户独立的公开随机值。同一口令加上不同盐，经同一函数也会得到不同记录。盐限制预计算和跨账户复用。为了让猜测本身更贵，还需要有成本参数的 **口令派生函数（Password-Based Key Derivation Function, PBKDF）**。

- 讲义用历史 `crypt()` 解释盐、算法标识和摘要可以同存，例如含 `$id$salt$hash` 的记录。具体格式和算法依系统而变。
- 旧 Windows 的 **LM 哈希（LM Hash）** 会将密码大写并分段，损失信息且把一个长口令分成较易猜的部分。**NT 哈希（NT Hash）** 使用 MD4 并保留大小写，讲义用其引出 **NTLM** 的挑战–响应（Challenge–Response）。
- **穷举（Brute Force）** 按空间试遍，**字典攻击（Dictionary Attack）** 优先试常见值。**彩虹表（Rainbow Table）** 用预计算链在存储和在线计算间折中。弱口令在快哈希下仍可能很快被猜到。讲义的口令审计工具演示说明了这个成本差异。

## 一次性口令（讲义第 59–63 页）

**一次性口令（One-Time Password, OTP）** 只在一次登录或一个短时间窗口内有效。这里的 OTP 指口令，L01 的同一缩写指一次一密。

**S/KEY 哈希链（Hash Chain）** 预先重复哈希，服务器先存最后一个值。登录时客户端反向交出前一项，服务器哈希一次与已存值比对，通过后把已存值换成这次收到的值。这样旧口令不能直接重放，链耗尽后要重新初始化。**RSA SecurID** 是讲义的时间同步令牌示例，同一时段服务器和令牌能计算对应验证码。
