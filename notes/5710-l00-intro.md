当别人能监听通信、改变输入或假冒身份时，系统还可以依靠什么？这门课从密码学、网络协议和程序漏洞入手。

## 课程地图（讲义第 1–12 页）

- **应用密码学（Applied Cryptography）** 研究如何把明文变成密文、如何分发密钥，以及如何验证数据和身份。L01–L04 从对称加密讲到公钥、签名、哈希与口令。
- **系统安全（System Security）** 从程序如何在内存中运行入手。L05 用数组越界说明一个普通的写入错误为什么可能影响控制流。
- **网络与 Web 安全（Network and Web Security）** 把证书放进网络协议，再看链路、传输、DNS、浏览器和无线网络各自信任什么。对应 L06–L11。

## 先写威胁模型（讲义第 13–19 页）

**威胁模型（Threat Model）** 说清攻击者能接触什么、能改变什么，以及系统想保护什么。**被动攻击（Passive Attack）** 只观察，例如偷听通信或分析谁在跟谁通信。**主动攻击（Active Attack）** 会改变系统收到的东西，例如篡改、伪装、中断或重放消息。

| 安全目标 | 用一句话判断 |
| --- | --- |
| **保密性（Confidentiality）** | 无权的人能读到内容吗？ |
| **完整性（Integrity）** | 内容被改动以后，接收者能发现吗？ |
| **可用性（Availability）** | 合法用户需要服务时，服务还能响应吗？ |
| **身份认证（Authentication）** | 通信对象或消息来源确实是所声称的吗？ |
| **不可否认性（Non-repudiation）** | 第三方能根据什么证据判断某人确实签过一份文件？ |

前三项常合称 **CIA 三要素（CIA Triad）**。例如，服务器一直在线但会把订单发给错误的人，可用性正常，保密性和身份认证仍值得检查。

## 从古典密码到现代密码（讲义第 20–30 页）

**密码学（Cryptography）** 构造和分析安全机制。**密码分析（Cryptanalysis）** 研究机制在什么条件下会泄露信息或失效。讲义用古典替换密码、二战时期的 Enigma、之后的 Diffie–Hellman 与 RSA 串起这段历史。互联网时代把密码学用到在线身份认证、数字签名等场景。

发送者对 **明文（Plaintext）** 和 **密钥（Key）** 做 **加密（Encryption）** 得到 **密文（Ciphertext）**，接收者用相应密钥 **解密（Decryption）**。在 **对称加密（Symmetric Encryption）** 中，双方共享秘密。安全性应来自密钥和设计，算法可以公开接受检验。

## 对称密钥和公钥怎么配合（讲义第 31–42 页）

- **凯撒密码（Caesar Cipher）** 按字母表固定移位。例如移三格时，CAT 变 FDW。可选移位太少，足以逐一尝试。
- **一次一密（One-Time Pad, OTP）** 用与消息等长的均匀随机密钥做异或，并且只用一次。它的保密性来自随机性，成本则是长密钥的分发与存储。
- **流密码（Stream Cipher）** 从短种子生成 **密钥流（Keystream）** 再逐位异或。**分组密码（Block Cipher）** 在给定密钥下把固定大小的分组做可逆变换。长消息要用加密模式来处理。
- **公钥密码学（Public-Key Cryptography）** 把公钥和私钥分开。**Diffie–Hellman 密钥交换（DH Key Exchange）** 让两端协商共享值，**RSA** 可用来讲解公钥加密和数字签名。日常协议常组合公钥机制和更高效的对称加密。
- **模运算（Modular Arithmetic）** 只保留除以某个数后的余数。课程还会用到 **整数分解（Integer Factorization）** 与 **离散对数（Discrete Logarithm）**。算法的安全假设要说明问题难度和所用参数。

## 从地址到浏览器的安全边界（讲义第 43–62 页）

- **HTTPS** 是在 **传输层安全协议（Transport Layer Security, TLS）** 上跑 HTTP。证书与 **公钥基础设施（Public Key Infrastructure, PKI）** 帮助客户端判断服务器身份。**虚拟专用网络（Virtual Private Network, VPN）** 让网络流量经过受保护的通道。
- 局域网会用 **地址解析协议（Address Resolution Protocol, ARP）** 找下一跳的链路地址，互联网用 **域名系统（Domain Name System, DNS）** 解析名字。两处都会因相信错误的数据而把流量送错。**分布式拒绝服务（Distributed Denial of Service, DDoS）** 则挤占正常请求所需的资源。
- **跨站请求伪造（Cross-Site Request Forgery, CSRF）** 涉及浏览器自动附带登录凭据。**SQL 注入（SQL Injection）** 出现在应用把输入当成数据库语句的一部分时。旧版浏览器案例引出 **栈（Stack）** 和 **缓冲区溢出（Buffer Overflow）**。
