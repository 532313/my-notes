公钥机制解决「开始通信时还没有共享秘密」和「如何让第三方验证签名」的问题。计算题先写清模数、谁有哪把密钥，以及所求的是共享值、密文还是签名。

## Diffie–Hellman 与所需的数学（讲义第 1–16 页）

n 个人若两两使用不同的对称密钥，需要 n(n−1)/2 把。**密钥交换（Key Exchange）** 让两端在公开参数上协商一个共享秘密。**Diffie–Hellman（DH）** 的双方各取秘密指数 a、b，发出 `A = g^a mod p` 和 `B = g^b mod p`。一方算 `B^a`，另一方算 `A^b`，都得到 `g^(ab) mod p`。后续协议用共享值派生会话密钥。公开值本身没有证明发送者是谁，认证见 L06。

- **群（Group）** 上的运算封闭、满足结合律，有单位元和逆元。模 n 下与 n 互质的余数在乘法下构成群，元素个数是 **欧拉函数（Euler’s Totient Function）** `φ(n)`。若 p 是质数，`φ(p) = p−1`。互质模数相乘时，对应的欧拉函数值也相乘。
- **生成元（Generator）** 的幂能遍历它所生成的群。给定生成元和某个幂值，反求指数是 **离散对数问题（Discrete Logarithm Problem, DLP）**。从两个公开幂值求共享值是 **计算型 Diffie–Hellman 问题（Computational DH, CDH）**。
- **快速模幂（Fast Modular Exponentiation）** 用反复平方得到 `g, g², g⁴, g⁸, …` 的模值，再按指数的二进制位选取并相乘。每一步都取模，避免存下巨大的整数。

## RSA 的密钥、加解密与正确性（讲义第 17–30 页）

1. 选两个不同的大质数 p、q，算 `n = pq` 和 `φ(n) = (p−1)(q−1)`。
2. 选与 `φ(n)` 互质的公开指数 e。用 **扩展欧几里得算法（Extended Euclidean Algorithm, EEA）** 求解 `ex + φ(n)y = 1`，令 **乘法逆元（Multiplicative Inverse）** `d = x mod φ(n)`。
3. 公钥为 (e, n)，私钥部分是 d 等秘密参数。教学公式为 `C = M^e mod n`、`M = C^d mod n`，要求编码后的 M 在模数范围内。

因为 `ed = 1 + kφ(n)`，当 M 与 n 互质时，**欧拉定理（Euler’s Theorem）** 直接解释为什么能还原。若 M 不是单位元，可以分开在模 p、模 q 下论证，再用 **中国剩余定理（Chinese Remainder Theorem, CRT）** 合并。课件示例 p=17、q=11，得到 n=187、φ=160，取 e=7 时 d=23。消息 88 加密为 11，再还原为 88。

知道 p 和 q 就能求 d。模数位数与对称密钥位数不能直接对比，二者依赖不同问题。公开指数适当选小可减少公开运算开销，私钥指数要满足安全参数要求。

## RSA 参数和消息编码（讲义第 31–45 页）

裸 RSA 直接处理整数，具有确定性。同一把公钥加密同一明文时结果相同。共用模数、随机生成质数的质量差、公开了 φ(n)，都会破坏原先的安全假设。讲义的 OpenSSL 截图展示私钥文件与公钥文件中哪些字段可以公开，也展示了消息编码和 RSA 幂运算是两步。

**最优非对称加密填充（Optimal Asymmetric Encryption Padding, OAEP）** 在编码时引入随机种子，用掩码将种子与消息互相绑定，然后再进行 RSA 运算。接收者需要检查编码是否有效。讲义对比了历史上的 **PKCS #1 v1.5**。**混合加密（Hybrid Encryption）** 只用公钥机制保护随机会话密钥，实际消息交给带认证的对称加密，避免逐块用裸 RSA。

## ElGamal 如何使用临时随机数（讲义第 46–51 页）

接收者选私钥 x，公钥含 `Y = g^x mod p`。发送者每次选新的随机数 k，密文两部分是 `r = g^k mod p`、`s = M·Y^k mod p`。接收者能算出 `r^x = Y^k`，因此用它的逆元恢复 M。

第 50 页例子在模 11 下用 g=2、x=5、k=3 加密消息 7，公钥幂值是 10，密文是 (8, 4)，解密回到 7。同一 k 会重复同一个掩码。保密性的常见论证要说明具体群和 **判定型 Diffie–Hellman 假设（Decisional DH, DDH）**，包括共享幂值能否和随机群元素区分。

## 离散对数的计算方法（讲义第 52–61 页）

**小步大步法（Baby-Step Giant-Step, BSGS）** 把指数写成 `j + iN`，把一部分幂值存表，另一部分用来匹配，时间和存储规模大致是群阶的平方根。**Pohlig–Hellman 方法** 利用群阶分解，在较小的素数幂阶子群中分别求解，然后用 CRT 合并。这解释了为什么群阶的因子结构和参数大小都影响安全。

例如，同时满足 `x mod 3 = 2`、`x mod 5 = 3`、`x mod 7 = 2` 的最小非负值是 23，其他解与它相差 105 的整数倍。

## 数字签名与公钥验证（讲义第 62–69 页）

**数字签名（Digital Signature）** 包含密钥生成、签名和验签。签名者用自己的私钥，验证者用签名者的公钥。签名要覆盖完整消息，消息内容依然可以是公开的。裸 RSA 的乘法结构可能造成签名可伪造。实际签名方案先对消息做哈希，再按标准编码，由验证者重新计算摘要并检查格式和签名。

讲义末尾的演示先从消息计算摘要并生成签名，再验证签名是否和消息摘要匹配。加密填充和签名编码各有目的，检查私钥和公钥的归属可以防止把两个流程记反。
