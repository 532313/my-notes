域名解析的关键是找到谁有权回答。拒绝服务的关键是找出哪个资源先用尽。把这两种问题分开，就容易理解为什么 DNSSEC 和限流解决的是不同故障。

## 域、区与一次解析（讲义第 1–18 页）

**域名系统（Domain Name System, DNS）** 管理一棵层级树。**域（Domain）** 是从某个名字往下的子树。**区（Zone）** 是某组 **权威服务器（Authoritative Name Servers）** 负责的记录范围。如果把子域委托给另一组服务器，子域仍在原域的树里，它的数据由另一区管理。

假设应用要解析 `www.example.net`。它把问题交给本机的解析组件，后者可按照本机配置先查 hosts，再交给 **递归解析器（Recursive Resolver）**。缓存未命中时，解析器通常先向根问 .net 的去处，再向 **顶级域（Top-Level Domain, TLD）** 服务器问 example.net 的权威地址，最后向权威服务器问记录。解析器向这些服务器逐步查询叫 **迭代查询（Iterative Query）**。根和 TLD 回的是委托线索，不必知道最终地址。

回复通常分为 **问题（Question）**、**应答（Answer）**、**权威（Authority）** 和 **附加（Additional）** 四部分。附加部分可提供解析下一跳所需的相关记录。**存活时间（Time to Live, TTL）** 限制记录在缓存中可停留多久。Linux 课件还以 `/etc/hosts` 和 `/etc/resolv.conf` 说明本机可影响名字来源与解析器选择。

## 缓存投毒与验证（讲义第 19–35 页）

**缓存投毒（Cache Poisoning）** 让解析器把不可信的记录存为正确结果，后续用户可能继续收到同一错误。主机配置被改、本地或远程伪造回复、信任恶意权威服务器带来的越权附带数据，都是课件的威胁模型。解析器应核对回复对应的待处理查询，并限制一个区能够为哪些名字提供可信记录。仅匹配 ID 等字段只能提高伪造难度。

| 检查 | 验证的对象 |
| --- | --- |
| **DNS 安全扩展（DNS Security Extensions, DNSSEC）** | 验证 DNS 数据来源与完整性。通过受信的根开始，父区的 **DS（Delegation Signer）** 记录绑定子区密钥，子区的 **DNSKEY** 用于验证记录集签名 **RRSIG**。 |
| **TLS 证书验证（TLS Certificate Validation）** | 连接到解析得到的 IP 后，检查对端是否为原本要访问的主机名、证书是否可信，以及服务器是否持有相应私钥。 |

DNSSEC 的信任随域名委托层级传递。HTTPS 的信任通过 CA 链传递。DNSSEC 的签名也不会把 DNS 查询内容加密。

## DoS 会耗尽什么资源（讲义第 36–47 页）

**拒绝服务（Denial of Service, DoS）** 让合法用户无法使用服务。**SYN 洪泛（SYN Flood）** 针对等待三次握手完成的 **半开连接（Half-Open Connection）** 状态。**SYN Cookie** 将可验证的信息放入服务器的初始序列号，收到合法 ACK 后才分配完整连接状态。因此在特定情况下能减少等待队列占用。

**分布式拒绝服务（Distributed Denial of Service, DDoS）** 来自许多源。直接洪泛消耗目标资源，**反射（Reflection）** 让第三方的回复流向受害者，**放大（Amplification）** 使回复体量大于请求。讲义用历史 Smurf 案例说明广播放大的影响。防护要看瓶颈类型，常用措施有源地址验证、上游过滤或速率控制、监测与事件溯源。SYN Cookie 主要减轻连接状态压力，传输链路的容量仍有上限。

## 蠕虫、僵尸网络与观测（讲义第 48–61 页）

**病毒（Virus）** 寄生于程序或文件。**蠕虫（Worm）** 可自行在网络传播。讲义用 Morris、Code Red 和 Nimda 对比不同传播途径和覆盖范围。

**随机恒定传播模型（Random Constant Spread, RCS）** 把已感染比例记为 a，增长率写成 `da/dt = K·a·(1−a)`。刚开始感染源少，增长较慢。感染比例约一半时增长最快。接近饱和时，剩余易受影响的机器变少，增长放缓。这是课堂的简化模型。

**僵尸网络（Botnet）** 由许多受控设备构成。集中架构经 **命令与控制（Command and Control, C2 / C&C）** 服务器分发指令，分布式架构可经对等节点传递。**蜜罐（Honeypot）** 是隔离的诱饵系统，用来观察可疑行为。修补服务、限制传播路径、监测异常连接是对应的防御方向。

## 网络诊断工具与异常连接（讲义第 62–67 页）

**Netcat** 能读写 TCP 或 UDP 字节流，适合在获授权的环境做连通性诊断。课件也用它说明 **后门（Backdoor）** 为什么可能表现为异常监听或主动连外。防守时结合进程身份、连接目的地、授权配置和系统日志来判断。
