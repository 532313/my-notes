TCP、TLS 与 VPN

TCP, TLS and VPNs

TCP 让两端按顺序收到字节。TLS 在连接上协商密钥、验证对端并保护数据。VPN 可以把原本单独发送的整个 IP 包放入受保护通道。这三个机制常同时出现。

TCP delivers bytes in order. TLS negotiates keys, authenticates peers and protects data on a connection. A VPN can carry whole IP packets over a protected channel. These mechanisms often appear together.

TCP 序列号怎样数到下一字节

How TCP sequence numbers count bytes

TCP 连接的 四元组（Four-Tuple） 是源 IP、源端口、目的 IP、目的端口。序列号（Sequence Number, SEQ） 指这段数据的第一个字节位置，确认号（Acknowledgment Number, ACK） 告诉发送者下一步期待哪个字节。TCP 传的是字节流，应用需要自己定义消息边界。

A TCP four-tuple is the source IP and port plus the destination IP and port. The sequence number (SEQ) gives the position of the first byte in a segment. The acknowledgment number (ACK) tells the sender which byte is expected next. TCP carries a byte stream, leaving applications to frame their own messages.

三次握手（Three-Way Handshake） 用 SYN、SYN-ACK、ACK 让双方知道对方的初始序列号。例子中客户端 SYN 的 seq=100，服务器以 seq=400、ack=101 回应。客户端再发 seq=101、ack=401。因为 SYN 占一个序列号。随后客户端从 101 开始发送 20 字节，服务器期待下一个字节 121。纯 ACK 不消耗序列号。正常收尾中，两端分别用 FIN 和 ACK 关闭各自发送方向，FIN 也占一个序列号。

The three-way handshake uses SYN, SYN-ACK and ACK to exchange initial sequence numbers. In a toy example, the client sends SYN with seq=100. The server replies with seq=400 and ack=101. The client replies with seq=101 and ack=401. A SYN occupies one sequence position. If the client then sends 20 bytes starting at 101, the server expects 121 next. A pure ACK consumes no sequence position. Each side normally closes its sending direction with FIN and ACK. A FIN also occupies a position.

连接重置（Reset, RST） 是 TCP 的控制信号。若未经认证的传输控制信息被错误接受，应用可能掉线，即使 TLS 保护数据内容。查看端口时，「有进程在监听」与「可以由外部访问」也不同，中间还有防火墙和路由。防守方会检查服务暴露情况与真实策略是否一致。

A reset (RST) is a TCP control signal. Incorrect acceptance of unauthenticated transport control data can interrupt an application even if TLS protects its content. A listening port and an externally reachable service can differ because of routing and filtering. Defenders compare actual exposure with their policy.

TLS 1.2 握手逐步读

Reading a TLS 1.2 handshake

握手层（Handshake Layer） 负责协商参数、验证身份和建立密钥。记录层（Record Layer） 将握手和应用数据装进 TLS 记录。这里按讲义中 TLS 1.2 的 RSA 密钥交换示例解释，使用临时 DH 等套件时部分消息和认证动作会不同。

The handshake layer negotiates parameters, authenticates identity and establishes keys. The record layer packages handshake and application data. This walkthrough follows the TLS 1.2 RSA key-exchange example used in the slides. Suites using ephemeral DH or other mechanisms can have different messages and checks.

顺序 消息 它解决什么问题
1 ClientHello 客户端提供随机数、可接受的版本和密码套件。
2 ServerHello + Certificate 服务器选择套件，提供随机数及证书链。客户端验链并核对主机名。
3 ClientKeyExchange 本例用服务器公钥保护预主密钥。两端从预主密钥与 Hello 随机数导出主密钥，再导出各方向的流量密钥。
4 ChangeCipherSpec 通知对端在本方向启用协商出的记录保护。
5 Finished 用协商秘密与此前的握手记录计算校验，双方确认参数和握手内容一致。
Step Message What it does
1 ClientHello Sends a client random value, supported versions and cipher suites.
2 ServerHello + Certificate Selects a suite, supplies a random value and sends a certificate chain. The client validates the chain and hostname.
3 ClientKeyExchange In this example the server public key protects a premaster secret. Both parties derive a master secret and direction-specific keys using the agreed inputs.
4 ChangeCipherSpec Signals the move to the negotiated record protection in that direction.
5 Finished Checks the handshake using the negotiated secret and earlier handshake messages.

密码套件（Cipher Suite） 决定这条连接用到哪些密码机制。客户端写密钥匹配服务器对应的读密钥，服务器写密钥匹配客户端的读密钥，两个方向各自产生保护。仅验证证书链还没有检查完整的握手。握手记录（Handshake Transcript） 参与 Finished 的验证，让消息的前后关联得到确认。

A cipher suite selects the cryptographic mechanisms for the connection. The client's write key matches the server's corresponding read key, and vice versa. The directions have separate protection state. Verifying the certificate chain leaves the rest of the handshake to check. The handshake transcript contributes to Finished and binds the messages together.

记录、会话与恢复

Records, sessions and resumption

记录头提供内容类型、版本和长度。应用数据可以分成多条记录。在旧式 TLS 1.2 CBC 示例里，对记录内容和隐式序号等计算 MAC，再按套件加密。AEAD 套件将加密与认证交给同一模式。接收者只在得到有效记录后使用数据。记录顺序参与认证，一条记录是否可接受还取决于它所处的位置。

The record header gives content type, version and length. Applications can use several records. In the older TLS 1.2 CBC example, a MAC covers record data and fields such as the implicit sequence number before the suite applies encryption. An AEAD suite combines encryption and authentication. The receiver uses successfully verified data. The authentication state also ties a record to its position.

对象 保存了什么
会话（Session） 一次协商得到的可复用状态，例如套件、主密钥和可用会话标识。
连接（Connection） 本次通信的随机值、双向读写密钥和记录序号。
Object What it holds
Session Reusable negotiated information, such as the suite, master secret and available session identifier.
Connection Random values, direction-specific read and write keys, and record numbers for this exchange.

会话恢复（Session Resumption） 例子中，服务器找到客户端请求的旧会话，从缓存的主密钥和新的随机数导出本次连接的密钥。因此可省去部分握手，又不需要沿用上一次连接的流量序号。关闭时可以通过 Alert 消息有序结束保护。

In the session resumption example, the server finds the previous session and combines its cached master secret with fresh randoms to derive connection keys. This saves part of the handshake while using fresh connection state. An Alert can signal an orderly closing of the protected channel.

VPN 如何携带一个完整 IP 包

How a VPN carries a full IP packet

VPN 首先建立经认证的通道，再用路由选择哪些包进入通道。IPsec 隧道 在 IP 层封装整个原包。讲义的 TLS VPN 示例让用户态程序把完整 IP 包作为 TLS 连接中的数据来传。

A VPN first establishes an authenticated channel, then routes selected packets through it. An IPsec tunnel encapsulates the original packet at the IP layer. In the TLS VPN example, a user-space program transports entire IP packets as data over TLS.

本机应用 → 内核路由 → TUN → VPN 程序 → TLS 通道 → 对端 VPN 程序 → 对端 TUN/路由

Application → kernel routing → TUN → VPN program → TLS channel → peer VPN program → peer TUN/routing

TUN 交付三层 IP 包。TAP 交付二层帧。普通 socket 通常把应用数据交给程序，虚拟接口可让 VPN 程序处理包或帧本身。出站先读虚拟接口，再写隧道。入站方向反过来。只有由路由选中、并交给 VPN 的流量获得这段保护。

A TUN interface carries layer-three IP packets. TAP carries layer-two frames. A normal socket often gives the program application bytes, while a virtual interface can expose complete packets or frames. Read the virtual interface and write into the tunnel on output, and do the reverse on input. The channel protects traffic selected by the routing policy.
