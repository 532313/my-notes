进程内存与缓冲区溢出

Process memory and buffer overflows

把进程内存想象成有权限的地址空间。数组只占其中一段。课堂问题从「这一字节会写到哪里」开始，再问相邻数据是什么，以及操作系统与编译器能在哪一环检测或限制后果。

Think of process memory as an address space with permissions. An array occupies only one part. Start by asking where a byte is written, then identify the neighboring data and when the compiler or operating system can detect or limit damage.

从可执行文件到进程地址空间

From an executable to process memory

程序（Program） 是存储的指令和数据。进程（Process） 是运行中的实例，有自己的 虚拟地址空间（Virtual Address Space）。两个进程可使用同一个虚拟地址而映射到不同的内存。操作系统按 页（Page） 映射和控制读、写、执行权限。某些硬件访问还要求 页对齐（Page Alignment）。

A program is stored instructions and data. A process is a running instance with its own virtual address space. Identical virtual addresses in two processes can map to different memory. The operating system maps pages and assigns read, write and execute permissions. Some hardware access also needs page alignment.

区域 典型内容
代码段（Text Segment） 执行的机器指令，通常被映射成可读和可执行。
数据段（Data Segment） 需要保留初值的全局和静态数据。
BSS 程序启动时清零的静态存储，程序文件主要记录所需空间。
堆（Heap） 动态分配的对象。分配器也可能通过额外映射取得内存。
栈（Stack） 部分局部对象和函数调用状态。
Region Typical contents
Text segment Machine instructions, normally mapped readable and executable.
Data segment Global and static data whose initial values are stored.
BSS Static storage cleared at startup, with its size recorded in the program file.
Heap Dynamically allocated objects. Allocators can also obtain separate mappings.
Stack Some local objects and function call state.

缓冲区（Buffer） 是一块有容量的存储。程序传递普通的 C 指针时，指针值说明地址，容量往往要另外提供。栈耗尽（Stack Exhaustion） 是深递归或局部对象过大把栈空间用完。缓冲区溢出（Buffer Overflow） 则是越过某一对象的边界，两者可以出现在不同情形。

A buffer is storage with a capacity. A normal C pointer provides an address, so capacity often needs to be passed separately. Stack exhaustion happens when recursion or large local allocations consume the stack. A buffer overflow crosses an individual object's bounds.

读懂一张栈帧图

Reading a stack-frame diagram

栈帧（Stack Frame） 保存一次调用用到的信息。讲义采用 32 位 x86 的示意模型。常见的逻辑顺序如下。

A stack frame holds information used by one function invocation. The slides use a 32-bit x86 teaching model. A typical logical sequence is as follows.

  1. 调用者（Caller） 按调用约定准备参数。CALL 记录下一条指令的地址，再转到被调用函数。
  2. 被调用函数（Callee） 可以保存旧帧指针并为局部数据留空间。ESP 即 栈指针（Stack Pointer），随压栈和弹栈变化。EBP 在课件模型里作 帧指针（Frame Pointer）。
  3. 函数结束时恢复保存的调用状态。RET 取得保存的 返回地址（Return Address）。它告诉处理器回到调用之后的指令。
  1. The caller prepares arguments according to the convention. CALL records the address of the next instruction and transfers control to the function.
  2. The callee can save the old frame pointer and reserve local storage. ESP is the stack pointer and changes with pushes and pops. EBP is the frame pointer in the slide model.
  3. Before finishing, the function restores saved state. RET obtains the saved return address, which directs execution to the instruction after the call.

调用约定（Calling Convention） 规定参数放在哪、哪些寄存器要保存、栈如何清理。在讲义的 32 位模型中，cdecl 由调用者清理栈参数，stdcall 由被调用者清理。做题按题给的图、栈增长方向、字节数和对齐写。优化或换架构时，参数可能在寄存器，局部变量也可能被优化掉，图不能硬套。

A calling convention specifies where arguments go, which registers are saved and how the stack is cleaned up. In the slide model, cdecl leaves stack argument cleanup to the caller, while stdcall leaves it to the callee. Use the diagram, growth direction, byte counts and alignment given in a question. Optimization or a different architecture can pass arguments in registers or remove some local variables.

逐字节判断是否越界

Checking bounds byte by byte

例子。有一个容量为 16 字节的字符数组，合法下标是 0 到 15。复制 n 字节的 C 字符串还要再写一个 NUL 终止符（NUL Terminator），所以要写下标 0 到 n。若 n=15，终止符在最后一格，刚好放下。若 n=16，正文虽能填满数组，终止符却会落在 16，已经越界。

Example. A character array has capacity 16 bytes and valid indices 0 through 15. Copying a C string of n bytes also writes a NUL terminator, so the writes cover indices 0 through n. With n=15, the terminator occupies the final slot and fits. With n=16, the text fills the array and the terminator at index 16 is out of bounds.

按这个顺序做题。先明确数组起点和容量，再求实际写入字节数，然后比较末字节与合法末地址。若题目使用小端序，小端（Little Endian） 表示低有效字节放在较低地址。地址升序和数字打印顺序可能不同。安全修复应拒绝放不下的数据，或按明确业务语义处理截断，并保留终止空间。

First determine the initial address and capacity. Count the bytes actually written, then compare the final write with the last valid address. A little-endian number stores the least significant byte at the lowest address. Address order may look different from the order in a printed number. A sound fix rejects data that cannot fit or handles truncation explicitly, while reserving room for the terminator.

一次越界写可能损坏相邻的普通数据。若受影响的是保存的返回地址或其他 控制数据（Control Data），控制流也可能受损。即使写入的虚拟页可写、程序没有立刻崩溃，对象边界仍然已被违反。这里关注缺失的检查和影响范围。

An out-of-bounds write can corrupt neighboring data. If it reaches a saved return address or other control data, it can affect control flow. A write can violate object bounds even when the virtual page is writable and the process does not crash immediately. The analysis focuses on the missing check and its impact.

三种防御各挡在哪一步

What each mitigation does

措施 保护时机与作用 仍要检查什么
边界检查（Bounds Checking） 写入前检查长度、容量和终止符。 截断或报错行为要符合调用方语义。
栈金丝雀（Stack Canary / StackGuard） 返回前核对保护值，发现被修改时停止。 与保护值无关的越界仍可能发生。
地址空间布局随机化（ASLR） 改变映射位置，使地址难预测。 仍须及时修复有界对象写入缺陷。
可写与可执行互斥（W^X） 页权限限制数据页被当成指令执行。 写入可写内存仍可造成数据破坏。
Measure When and how it helps What still needs checking
Bounds checking Checks length, capacity and termination before writing. Rejection or truncation must suit the caller.
Stack canary / StackGuard Checks a guard value before returning and terminates on corruption. Writes that do not touch the guard may still occur.
Address-space layout randomization (ASLR) Changes mapping locations and makes addresses harder to predict. The incorrect bounded-object write still requires a fix.
Write XOR Execute (W^X) Page permissions prevent writable data pages from being executed as instructions. Writes to writable memory can still corrupt data.

HW2 Q5 的答题方式适合每项措施。先说它检查什么或改变什么，再说它影响哪一步，最后说明源码里的错误如何修。多个措施可以叠加，真正修复发生在对长度和目标容量的校验上。

The structure of HW2 Q5 works for each measure. State what it checks or changes, identify the stage it affects, and explain how to fix the source-level defect. Combining protections helps, while the source fix comes from checking length against capacity.
