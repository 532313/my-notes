Orientation and security fundamentals

安全目标与威胁模型

Security goals and threat models

威胁模型（Threat Model） 明确攻击者的能力和系统的目标。同一个邮箱，面对只观察流量的旁观者、能修改请求的中间人和已经控制账号的人，需要不同的保护。作答时把能力写成具体操作，再判断系统还能信任哪些数据。

A threat model states the attacker's capabilities and the system's goals. An email service needs different protections against a traffic observer, an intermediary who can change messages, and someone who already controls an account. State the capabilities in concrete terms and identify which data can still be trusted.

安全目标 要问的问题 例子
保密性（Confidentiality） 无权的人能读内容吗？ 旁观者读不到邮件正文。
完整性（Integrity） 数据被改动后能否发现？ 服务器拒绝被篡改的转账金额。
可用性（Availability） 合法用户需要时还能用吗？ 重复请求耗尽连接会影响可用性。
身份认证（Authentication） 谁在声明身份或发送消息？ 浏览器确认服务器代表访问的域名。
不可否认性（Non-repudiation） 有何证据归属某项操作？ 第三方可验证某人的文件签名。
Goal Question Example
Confidentiality Who can read the data? An observer cannot read the email body.
Integrity Can a change be detected? The server rejects an altered payment amount.
Availability Can legitimate users obtain service when needed? Duplicate requests can exhaust connection capacity.
Authentication Who is making the claim or sending the message? A browser checks that the server represents the requested domain.
Non-repudiation What evidence attributes an action to someone? A third party can verify a document signature.

前三项简称 CIA。被动攻击（Passive Attack） 只观察，如窃听与流量分析。主动攻击（Active Attack） 会修改、注入、阻断或重放数据。即使正文加密，时间和长度有时仍可观察。题目若问「这个系统安全吗」，先说明考虑哪类攻击和哪项安全目标。

The first three form the CIA triad. A passive attack observes, as in eavesdropping or traffic analysis. An active attack modifies, injects, blocks, or replays data. Timing and length are sometimes observable even when the body is encrypted. When asked whether a system is secure, specify the attack model and the property under evaluation.

明文、密文与密钥

Plaintext, ciphertext and keys

发送者以 明文（Plaintext） M 和 密钥（Key） K 为输入，经 加密（Encryption） 得到 密文（Ciphertext） C。接收者用正确的密钥执行 解密（Decryption） 恢复 M。正确性（Correctness） 回答合法收发双方能不能还原。保密性（Secrecy） 回答观察者能从密文推断多少。

The sender takes a plaintext M and key K, applies encryption, and produces a ciphertext C. The receiver uses the appropriate key and decryption to recover M. Correctness asks whether the intended parties recover the message. Secrecy concerns how much an observer can infer from the ciphertext.

凯撒密码（Caesar Cipher） 固定移动字母。把 A 编为 0、Z 编为 25，密钥 3 让 E 的编号 4 变成 7，也就是 H。Y 的编号 24 加 3 后模 26 等于 1，也就是 B。只有少量移位可以尝试，字母频率也只发生平移。因此可逆并且看起来像乱码，仍可能很容易被分析。

A Caesar cipher shifts every letter by a fixed amount. Number A as 0 and Z as 25. With shift 3, E moves from 4 to 7, or H. Y has value 24, and adding 3 modulo 26 gives 1, or B. There are few shifts to try, and letter frequencies merely change position. A reversible but unreadable-looking result may remain easy to analyze.

机制 基本思路
流密码（Stream Cipher） 产生密钥流并逐段与消息组合。L01 讨论复用。
分组密码（Block Cipher） 对固定长度的块做可逆变换。L02 讨论怎样处理多块。
对称密钥（Symmetric Key） 两端共享秘密。n 人两两用不同密钥，共有 n(n−1)/2 对。
公钥机制（Public-Key Mechanism） 公布公钥，私钥由持有者保管。L03 用 DH、RSA 和签名说明用途。
Mechanism Basic idea
Stream cipher Generate a keystream and combine it with the message in pieces. L01 discusses reuse.
Block cipher Transform a fixed-size block reversibly. L02 covers multiple blocks.
Symmetric key The parties share a secret. Giving every pair among n people a distinct key takes n(n−1)/2 keys.
Public-key mechanism Publish a public key while its owner keeps the private key. L03 illustrates DH, RSA and signatures.

现代密码学明确困难假设，如整数分解和离散对数。公开算法可以接受检验，安全性依靠密钥、参数和协议设计。实际系统常用公钥机制建立会话密钥，再用对称方案保护大量数据。

Modern cryptography makes hardness assumptions explicit, such as integer factorization or discrete logarithms. A public algorithm can be inspected, while security depends on keys, parameters and protocol design. Many systems establish a session key with a public-key mechanism and protect bulk data with symmetric operations.

一次登录经过哪些安全边界

Security boundaries during a login

手机 → 无线接入点 → 网关 → 互联网 → 网站

Phone → wireless access point → gateway → Internet → website

  1. 链路安全（Link Security） 在无线终端与接入点之间起作用。经过下一跳时，会有另一条链路。
  2. 域名系统（DNS） 把名字解析成记录。能找到地址以后，还要确认地址上的服务器是谁。
  3. 传输层安全协议（TLS） 验证对端并保护应用数据。HTTPS 就是在 TLS 中传 HTTP。
  4. Web 会话（Web Session） 关联登录状态。网站还要验证修改资料等请求来自合法交互。
  5. 进程内存（Process Memory） 属于程序的运行环境。数据安全送达之后，接收代码仍要检查长度与格式。
  1. Link security can protect the hop between a wireless device and its access point. The next hop is a separate link.
  2. The Domain Name System (DNS) resolves names to records. Having an address leaves the peer's identity to be established.
  3. Transport Layer Security (TLS) authenticates the peer and protects application data. HTTPS carries HTTP inside TLS.
  4. A web session associates requests with sign-in state. A website still checks whether a change of account details comes from an authorized interaction.
  5. Process memory belongs to the application runtime. Secure delivery still leaves the receiver responsible for length and format checks.

机制的保护范围也不同。消息认证码（MAC） 让共享密钥的双方核验一条消息。数字签名（Digital Signature） 允许有公钥的人验签。虚拟专用网络（VPN） 保护被路由进隧道的流量。看后续章节时，每看到一种防御就说出它检查的对象和信任来源。

The mechanisms also differ in scope. A message authentication code (MAC) lets parties sharing a key verify messages. A digital signature can be checked by anyone with the signer's public key. A virtual private network (VPN) protects traffic routed through its tunnel. In later chapters, identify what every defense checks and where its trust comes from.
