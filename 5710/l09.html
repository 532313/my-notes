DNS、拒绝服务与蠕虫

DNS, denial of service and worms

DNS 解决「去哪里找某个名字」，DNSSEC 解决「回答是谁保证的」。拒绝服务题的切入点不同，要找到有限资源在哪里，为什么正常用户拿不到它。

DNS answers where to find a name, and DNSSEC helps verify who vouched for the DNS data. Denial-of-service questions start with a different issue. Find the limited resource and explain why legitimate users cannot obtain it.

域、区和一次域名解析

Domains, zones and one resolution

域（Domain） 是名字树上的子树。区（Zone） 是一组权威服务器管理的数据范围。父域里可以包含一个子域，但后者委托后会有自己的区。父区保存指向子区权威服务器的线索。

A domain is a subtree of names. A zone is the set of records managed by an authority. A child domain can remain in the parent's namespace while becoming a separately delegated zone. The parent publishes referral information.

以 www.example.net 为例。应用调用本机解析组件，系统可先查 hosts 和缓存。通常本机再向 递归解析器（Recursive Resolver） 请求最终结果。若无缓存，解析器从根找到 .net 的服务器，再询问 .net 获得 example.net 的委托，最后向相应 权威服务器（Authoritative Name Server） 取得记录。解析器向上游逐级询问的是 迭代查询（Iterative Query）。递归描述替客户找到结果的职责，迭代描述取得线索的过程。

Consider www.example.net. The application calls a local resolver component, which may consult hosts and caches. It usually asks a recursive resolver for the final result. On a cache miss, the resolver can ask the root for .net, ask .net for the delegation to example.net, then obtain its record from an authoritative name server. The resolver's step-by-step exchanges are iterative queries. Recursion is the service of finding a result for the client. Iteration is a method of following referrals.

存活时间（Time to Live, TTL） 控制缓存有效时间。如果解析器在 t=0 得到 TTL=120 秒的记录，t=80 时允许使用仍有效的记录，剩余 TTL 约 40 秒。过期后需要按策略重新获得有效数据。

A time to live (TTL) bounds how long a cache can reuse a record. A record received at t=0 with TTL 120 seconds has about 40 seconds left at t=80. After expiration, the resolver needs valid data according to policy.

DNSSEC 和 HTTPS 验证谁

What DNSSEC and HTTPS each authenticate

缓存投毒（Cache Poisoning） 让解析器把错误信息留在缓存中，之后的请求也可能拿到同一结果。记录与待查询请求匹配，只能部分降低假回复风险。解析器还要限制一个区有权为哪些名字提供记录，并按配置验证签名。

Cache poisoning places incorrect data in a resolver cache, making later clients receive the same result. Matching a response to a pending query provides only part of the check. The resolver also limits which names a zone can speak for and validates signatures according to its configuration.

DNS 安全扩展（DNSSEC） 检查 DNS 记录集的来源与完整性。验证者从预配置的根信任锚开始，再沿父区到子区走。父区的 DS（Delegation Signer） 记录绑定子区密钥。子区的 DNSKEY 提供验证公钥，RRSIG 覆盖一组资源记录。验证后的 DNS 数据仍可读。

DNS Security Extensions (DNSSEC) authenticate DNS record sets and protect their integrity. Start from a configured root trust anchor and follow delegations. The parent's DS (Delegation Signer) record binds a child key. The child's DNSKEY supplies a verification key, and an RRSIG covers a resource record set. The verified data remains readable.

HTTPS 则验证发来证书并完成握手的端点能否代表浏览器请求的主机名。即使 DNS 返回错误 IP，拿不到有效主机名证书和相应持钥证明的端点仍会因 TLS 检查失败。反过来，DNSSEC 验证通过并不加密 HTTP 正文。把两种链分别画出来，父区委托和 CA 颁证的角色就不易混。

HTTPS checks whether the peer presenting a certificate and finishing the handshake can represent the requested hostname. Even if DNS points at the wrong IP, a peer without a valid certificate for that name and the proper proof of possession fails TLS validation. Successful DNSSEC validation also leaves HTTP plaintext unencrypted. Draw the delegation chain and CA chain separately to keep the two roles clear.

先找耗尽的资源

Finding the exhausted resource

拒绝服务（Denial of Service, DoS） 让合法用户无法获得服务。首先要区分 网络带宽、连接状态、应用线程 及 处理时间。服务 CPU 不忙，链路仍可能已经满了。网络吞吐正常，应用线程仍可能被占着。

A denial of service (DoS) makes a service unavailable to legitimate users. Distinguish bandwidth, connection state, worker threads and processing time as possible bottlenecks. A link can be saturated while the server CPU is quiet. An application can run out of workers without saturating the link.

SYN 洪泛（SYN Flood） 针对等待 TCP 握手完成的 半开连接（Half-Open Connection）。传统做法在收到初始 SYN 时记住部分状态。SYN Cookie 将后续验证所需的信息放进服务器的初始序号，只有收到有效的最后 ACK 才分配完整连接状态。它针对等待队列与内存压力，链路带宽仍需要其他保护。

A SYN flood stresses half-open connections awaiting completion of the TCP handshake. A traditional response to the initial SYN stores some state. A SYN cookie encodes verification inputs in the server's initial sequence number and waits for a valid final ACK before allocating full state. It addresses backlog and memory pressure, while bandwidth needs separate protection.

分布式拒绝服务（DDoS） 来自多个源。反射（Reflection） 让第三方的响应流向受害者，放大（Amplification） 表示响应负载比触发它的请求大。讲义的 Smurf 是历史案例。定位时看瓶颈在哪里，再选择源地址验证、上游清洗、速率限制、容量隔离或监控响应。

A distributed denial of service (DDoS) comes from many sources. Reflection directs third-party replies toward the victim, and amplification means the response load exceeds the triggering request. Smurf is a historical illustration. Locate the bottleneck before selecting source-address validation, upstream filtering, rate controls, isolation, or monitoring and response.

病毒、蠕虫与僵尸网络

Viruses, worms and botnets

病毒（Virus） 通常依附在程序或文件上。蠕虫（Worm） 可以自动通过网络传播。课件用 Morris、Code Red、Nimda 比较不同历史场景。僵尸网络（Botnet） 指被共同控制的一组设备，它可以使用集中 命令与控制（Command and Control, C2） 或分布式传递。

A virus often attaches to a program or file. A worm can propagate automatically across a network. The slides compare historical examples such as Morris, Code Red and Nimda. A botnet is a set of controlled devices, which can receive instructions through centralized command and control (C2) or distributed communication.

随机恒定传播模型（Random Constant Spread） 用 a 表示易受影响设备中已感染的比例。简化模型 da/dt=Ka(1−a) 同时看感染源比例 a 与仍可感染的比例 1−a。a=0.5 时乘积最大。刚开始源少，后期剩余设备少，两端增量都较小。这个模型为解释传播趋势服务。

The random constant spread model uses a for the fraction of susceptible devices already infected. The simplified equation da/dt=Ka(1−a) considers the infected fraction a and the remaining fraction 1−a. Their product peaks at a=0.5. At the beginning few sources exist, and at the end few devices remain. The model explains the shape of the growth trend.

蜜罐（Honeypot） 在隔离环境中收集异常行为。正常诊断工具也可能出现在异常连接中。排查时把进程、连接方向、访问权限和事件日志放在一起，验证行为是否符合该设备角色。修补、隔离和监测可以降低传播与控制风险。

A honeypot collects suspicious behavior in an isolated setting. Ordinary diagnostic tools can also appear in unusual connections. Review process identity, connection direction, privileges and event logs together to see whether activity fits the device's role. Patching, isolation and monitoring help manage propagation and control risks.
