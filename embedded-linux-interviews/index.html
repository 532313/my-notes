逐题参考答案

1采集、控制和上报怎么串成一条系统链路？

参考答案：我先把数据流和控制流分开。数据从采集到编码，再进入有界队列，由落盘和上传端按各自需求消费；控制命令有明确状态和应答。上传慢时不能无上限堆帧，预览可丢旧帧，必须留存的数据要独立写盘。最后用断网、慢盘、重启三个测试核验退化行为。

2端侧模型怎么选？

参考答案：先明确任务能容忍的误差、设备内存和时延预算。拿同一批代表性样本比较准确率、端到端延迟、峰值内存，再选择轻量模型或量化方案。不要只比较模型推理这一段；预处理和搬运可能才是瓶颈。

3部署到设备后效果变差，怎么定位？

参考答案：同一输入分别在桌面和板端跑，先比预处理张量的尺寸、颜色顺序、归一化，再逐层比输出。确认 FP32 基线后一次只改变一个因素，例如量化、算子后端或后处理阈值。留一组固定输入和输出供回归。

4Linux 进程 CPU 占用约 90%，先看哪里？

参考答案：先确认是否持续、百分比按单核还是整机计。用 top -H -p PID 查热点线程，再用 perf 采样调用栈或给流水线分段打点。先区分忙轮询、内存搬运和软件编解码，再在相同负载下复测 CPU、延迟和掉帧率。

5C 中怎么选内存拷贝方法？

参考答案：两段确认不重叠用 memcpy，可能重叠用 memmove。先验证容量与长度，字符串另外保证 NUL 结尾。含非平凡成员的 C++ 对象不能用逐字节复制代替正常复制构造。

6深拷贝和浅拷贝的区别是什么？

参考答案：拷贝指针地址通常只是共享资源；深拷贝会分配新资源并复制内容。区别在于修改是否互相影响、谁负责释放。用缓冲区结构体举例：只复制指针后两份结构占有同一块内存，若都 free 就会二次释放。

逐题参考答案

1多个线程访问共享变量有什么风险？

参考答案：普通变量存在并发写，或一个线程写另一个线程读而没有同步，在 C++ 中就是 data race（数据竞争），行为未定义。单独计数可用 atomic；多个字段之间有一致性约束，要用同一把锁或让单线程独占状态。

2两个线程同时做 count++，会发生什么？

参考答案：自增包含读取、加一和写回。两个线程可能读到同一个旧值，最终只留下一个加一；对普通 C++ 变量这只是可能现象，语言层面是未定义行为。独立统计计数可用 fetch_add，只有不依赖该计数同步其他数据时才考虑 relaxed。

3函数调用时栈里会放什么？

参考答案：由 ABI（应用二进制接口）定哪些参数和返回值用寄存器，溢出的参数可能上栈。栈帧可含保存的寄存器、局部变量和对齐填充。叶子函数或内联函数甚至可能不建立独立栈帧；看反汇编验证。

4结构体按值传递和传指针有什么区别？

参考答案：按值调用的形参是语义上的副本，改副本不会改调用者的字段；但指针字段仍指向同一资源。传指针可直接操作原对象，适合大对象，不过要约定是否可写、是否为空和生命周期。

5派生类与基类有同名字段时，访问哪个？

参考答案：成员查找按表达式的静态类型和作用域决定。派生类的同名字段隐藏基类字段，可用 obj.Base::field 显式访问。普通数据成员没有虚分派，不要套用虚函数的规则。

6static 的含义跟位置有什么关系？

参考答案：C 中，文件作用域 static 让名字具有 internal linkage（内部链接）；块作用域变量仍是块作用域，但有静态存储期。C++ 的 static 成员属于类，静态成员函数没有 this。说清链接性和生命周期是两个维度。

7哈希表冲突怎么解决？

参考答案：拉链法把同桶元素挂在一起；开放寻址在其他槽里探测，删除往往要用墓碑。负载因子过高会提高冲突成本，扩容需要重新散列；平均 O(1) 不是最坏保证。

8怎么判断单链表有环？

参考答案：Floyd 快慢指针从头出发，慢指针每轮一步、快指针两步；快指针不能继续则无环，有环时两者在环内相遇。先判 fast 和 fast->next 是否为空。时间 O(n)，额外空间 O(1)。

bool hasCycle(const Node* head) {
    auto slow = head, fast = head;
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return true;
    }
    return false;
}

逐题参考答案

1驱动层和应用层的边界怎么划？

参考答案：底层管寄存器、IRQ、DMA 和硬件资源，往上提供稳定接口及明确错误码。应用管策略，不直接操作寄存器。调试时把入口参数、硬件状态和回调事件分别打点，定位到底是哪层出错。

2ADC、PWM、DIO 和 CAN 驱动怎么验证？

参考答案：ADC 喂已知电压检验偏差和满量程；PWM 用示波器测周期、占空比和边界；DIO 验证方向、电平及上下拉；CAN 用第二节点或分析仪核对帧、ACK 和错误计数。每类都设计一个正常与一个故障用例。

3CRC 能检查什么？

参考答案：发送端按多项式计算校验值，接收端用同一参数验证。CRC 用于检错，不能靠它修复损坏的数据，也不提供密码学认证。联调时对齐初值、反射、异或值及字节顺序，用标准测试向量和单比特翻转检查。

4UART 偶发错字节怎么调？

参考答案：先测电平、地、波特率和帧配置，再读 framing、parity、overrun 等状态。同步抓波形和收到的原始字节，辨别对端发错、线路干扰还是本地处理不及时。上层用长度、CRC 与超时重新找帧边界。

5UART 的 DMA 接收异常怎么查？

参考答案：先抓 DMA 写位置、剩余计数、传输错误及 ring buffer（环形缓冲区）读位置，确认没有生产者覆盖未消费字节。检查半满/满和空闲中断两类通知是否重复计算。带 D-cache 的 MCU 还要查缓冲区可达性、缓存维护和地址对齐。

6CAN 出现 Error Frame 或 Bus-Off 怎么分析？

参考答案：先区分 ACK、位、格式或 CRC 错误，检查速率、终端电阻、接线和另一节点状态。Bus-Off 表示节点因发送错误累积退出总线，恢复要按控制器要求和整车策略执行；记录计数和恢复结果，避免接线未修好就无限重复恢复。

7OBD 和诊断下载是什么关系？

参考答案：OBD 是车载诊断的法规与协议体系；不能把它直接等同于 UDS 刷写。典型 UDS 下载经历会话切换、授权、前置条件、分块传输、完整性校验与退出/重启。实际服务顺序和失败恢复要看 ECU 规范。

逐题参考答案

1I²C 读寄存器时，线上信号怎么走？

参考答案：主机 START 后发 7 位设备地址与写方向，设备 ACK，再写寄存器地址。常见读法用 repeated START 切换到读方向；最后一个读字节由主机回 NACK，再 STOP。具体序列仍以芯片手册为准。

2Device Tree（设备树）解决了什么问题？

参考答案：它用节点描述不能自动枚举的硬件和资源，而非把驱动代码放进去。例如 I²C 子节点给出地址、compatible 和中断。内核根据 binding 解析资源并匹配驱动；调试要检查实际启动加载的 DTB。

3Linux 外设驱动怎么注册，又怎么用起来？

参考答案：以 I²C client 为例：注册 i2c_driver，核心把设备与驱动匹配后调用 probe，probe 获取资源和初始化芯片，再接入 input、IIO 或字符设备。用已绑定驱动、日志和实际用户态读数分别验证各阶段。

4为什么要建立 /dev 设备节点？

参考答案：字符设备节点保存类型及主次设备号，给应用一个稳定入口。open 时内核按设备号找到已注册 cdev，转入对应操作；没有可访问节点不代表驱动没 bound，反过来有一个手建节点也不保证有有效驱动。

5字符设备通常实现哪些 file_operations？

参考答案：按需要提供 open、release、read、write、unlocked_ioctl、poll、mmap 等，不是全部必填。比如只读事件流至少要定义阻塞/非阻塞 read，若支持 epoll 再实现 poll 并在事件就绪时唤醒。

6驱动自己的 open 函数里适合放什么？

参考答案：从 inode 找到设备上下文并设 file->private_data，判断设备仍在线及是否允许独占，必要时分配 per-open 状态。硬件一次性初始化通常放 probe；open 失败要逆序清理，release 对应回收。

7为什么内核需要 file_operations 这层接口？

参考答案：应用只调用 open/read/ioctl 等统一 syscall（系统调用）。VFS 通过一组函数指针分派到具体实现，应用不需要知道硬件或选择内部驱动函数；驱动仍要检查长度、访问权限和用户指针。

8GPIO、引脚复用和 IRQ 分别怎么申请？

参考答案：引脚功能通常由 pinctrl 配置。GPIO 用 descriptor API 获取；IRQ 可由固件资源提供，GPIO 线作中断时按实际映射用 gpiod_to_irq。用 devm_request_threaded_irq 等注册，检查触发类型，并用 /proc/interrupts 和外设状态验证。

9AP3216C 是否有可复用的内核实现？

参考答案：别凭记忆保证有。先搜目标内核源码、Kconfig、compatible 和已有 IIO/光传感器驱动，再看板卡厂商树。如果无合适实现，才选接口、写寄存器访问和数据通道；上板对照手册验证读数与阈值。

10UART 至少要哪些信号线？SPI 与它哪里不同？

参考答案：典型板级全双工 UART 接 TX、RX、共同参考 GND，硬件流控时还可能用 RTS/CTS，无共享时钟。SPI 通常有 SCLK、片选和数据线，边沿由 CPOL/CPHA 决定。两种接口都要确认电平标准，TTL 不能直接等同 RS-232。

11在 Linux 源码里，选一个子系统怎么讲清读到的链路？

参考答案：挑能核验的最短路径，例如用户态读 /dev/input/eventX，经过 evdev、input core 直到驱动上报。标出入口、回调、阻塞点和日志；没有读过的目录或机制按待验证说。

12字符设备的异步通知是怎样工作的？

参考答案：一种方案是用户设 F_SETOWN 和 O_ASYNC，驱动在 fasync 回调登记 file，数据就绪后 kill_fasync 发 SIGIO。信号只是提示，数据仍由 read 取，不能一信号等于一事件；常见替代是 poll/epoll 加等待队列。

逐题参考答案

1RT-Thread 的任务优先级怎么设？

参考答案：列出周期、截止时间、运行时长和阻塞。采样或紧急控制优先，低优先级处理日志、上报；不要让高优先级任务忙等或长时间持锁。用最坏负载测最大响应时延，再决定是否需要优先级继承。

2FPGA 多时钟域的数据怎么同步？

参考答案：单比特稳定电平可用两级同步器降低亚稳态风险。窄脉冲用展宽、toggle 或握手，不能假定慢域一定采到。多比特数据可用异步 FIFO，指针跨域用 Gray 码；一起变化的数据不能简单逐位过双触发器。

3传感器温漂怎么处理？

参考答案：先在可控温度范围做静止测量，区分零偏和比例误差。建立温度到偏置的模型，运行时插值补偿；拿独立温度段验收，并区分温漂、热滞后与随机噪声。

4陀螺仪和里程计怎么融合？

参考答案：先校准时间、坐标系和单位。陀螺角速度用于短时预测，轮速里程计提供速度或位姿约束；在 EKF（扩展卡尔曼滤波）中分别建噪声，打滑时降权。用静止、直线、转弯和打滑对比单传感器与融合结果。

逐题参考答案

1项目如何交代所用模块和协议？

参考答案：从链路讲：控制器通过某接口读传感器、发电机指令，通过另一接口向上位机报告。每段交代速率、报文、失败处理和实测证据，个人负责范围单列。

2电机联调先验什么？

参考答案：先校验供电、驱动限流、方向和编码器符号，低占空比空载试转。闭环先调速度环再调位置环，用阶跃响应看超调和稳态误差；卡死、掉编码器或超流时要能安全停机。

3115200 8N1 在 1 ms 能传多少数据？

参考答案：每字节 1 起始位、8 数据位、1 停止位，理论 115200/10=11520 字节每秒，平均 11.52 字节每毫秒。实际还要扣空闲、帧头和校验，不是每个 1 ms 都固定收到相同整数个字节。

41 Mbit/s 下经典 CAN 的满载扩展帧每毫秒能发几包？

参考答案：假设 29 位 ID、8 字节 payload 和 3 位 intermission，不计填充约 131 位，每毫秒约 7.63 帧；按保守最坏位填充上界约 160 位，约 6.25 帧。重传和竞争会进一步降低。注意 CAN FD 和经典 CAN 的字段不同。

5联调 CAN 时该观察 CRC 吗？

参考答案：正常业务通常看有效载荷和错误计数；CRC 错帧不会当作正常帧交给应用。偶发坏帧则看控制器错误状态及分析仪的帧记录，区分 CRC、ACK、bit stuffing 和电气问题。

6STM32 的 CAN CRC 是硬件算还是软件算？

参考答案：常见 bxCAN 或 FDCAN 控制器在发送时生成链路层 CRC、接收时检验，正常不需应用手算。应用层额外 CRC（如报文端到端保护）是另一层，参数和校验范围由上层协议规定。

7经典 CAN 帧中的 ID、数据和 CRC 分别多大？

参考答案：标准 ID 11 位，扩展 ID 29 位；数据 0–8 字节；经典 CAN 的 CRC 序列 15 位，后接 delimiter（界定符）。别把字段位数说成帧数；CAN FD 另有不同载荷与 CRC 长度。

8Linux BSP 包含什么，如何证明自己用过？

参考答案：板级包通常涉及 bootloader、设备树、内核配置和驱动、根文件系统或板厂脚本。选一项说明怎么构建、部署、验证；例如改设备树后查 live DT、驱动绑定与实际输入事件。

9讲一个 Linux 用户态编程例子。

参考答案：选熟悉的接口说清打开设备、处理非阻塞 I/O 和退出回收。比如用 epoll 监听多个 fd，读到 EAGAIN 再返回事件循环，同时为超时、短读和断开设计测试。只把做过的部分说成经历。

10进程间怎么传消息？

参考答案：小字节流可用 pipe，结构化进程间通讯可用 Unix socket 或消息队列。共享内存减少复制，但要用锁、信号量或原子协议明确所有权。选择看消息边界、容量、阻塞和崩溃回收。

11FreeRTOS 在典型 Cortex-M 上通过什么中断触发调度？

参考答案：SysTick 递增系统 tick 并推进延时列表，必要时挂起 PendSV；主动 yield 或 ISR 唤醒高优先级任务也可请求切换。不是每次 tick 都必须换任务，也不是所有移植层都用这套中断。

12任务上下文在哪儿真正切换？

参考答案：常见 Cortex-M FreeRTOS port 用 PendSV，保存当前任务寄存器与栈指针，选择就绪任务并恢复其上下文。SVC 常用于启动首个任务（具体看移植实现），不要把 tick 处理等同切换本身。

13多任务共用一块大内存要管什么？

参考答案：先定义谁写、谁读、生命周期和锁粒度。多字段一致性用 mutex 或单写者队列，任务不能长期持锁。若还有 DMA 则另查 cache、一致性及 ownership，不能只加一把任务锁。

14FreeRTOS Queue（队列）怎么传数据？

参考答案：队列按建立时的元素大小复制；大块数据可传指针，但要明确定义回收及超时失败时的归属。任务可阻塞等待，ISR 必须用 FromISR 版本，根据唤醒结果请求调度。

15FreeRTOS 和 Linux 有哪些区别？

参考答案：嵌入式 FreeRTOS 常是同地址空间的任务与固定优先级调度，资源少，适合可分析的时延。Linux 提供进程隔离、虚拟内存与通用子系统，也有实时调度和 PREEMPT_RT。选型看隔离、生态及截止期。

16RTOS 实时性最重要的含义是什么？

参考答案：实时性关注是否在截止时间前完成，不是平均更快。列最坏中断屏蔽、锁阻塞和任务抢占；用压力场景量最大值、尾延迟和超期次数，再判断能否满足约束。

17Linux 软中断与硬件 IRQ 能简单对比成 Linux 慢、RTOS 快吗？

参考答案：不能。Linux 同样先接硬件 IRQ，SOFTIRQ（软中断）是延后处理机制；RTOS 也可把工作交给任务。测量要明确从外设边沿到 ISR、再到任务完成的两个区间，考虑配置和负载。

18USB 热插拔如何处理？

参考答案：区分设备枚举与应用打开。用户态可监听 udev/netlink 事件，按稳定属性识别目标，准备好后才能读写；拔出时停止提交、容错关闭 fd。验证重复插拔、传输中拔出及重新枚举。

19ROS 常见通信方式有哪些？

参考答案：Topic（话题）是异步发布订阅，Service（服务）是请求响应，Action（动作）适合长任务并可反馈、取消。以传感器数据、参数查询与导航目标分别举例；ROS 1 和 ROS 2 具体传输不同。

20ROS 和 socket 有什么关系？

参考答案：应用通常用 ROS API，不一定直接操作 socket；ROS 1 常见 TCPROS，ROS 2 常经 DDS 中间件走 UDP 等。调试区分发现、连接和数据面，再看 QoS、序列化和网络。

21怎么描述 MCU 和 SDK 的使用经验？

参考答案：按板卡、内核、使用的 SDK/HAL、外设及验证讲。把寄存器配置和库封装划清；没用过特定厂商就说可以从启动文件、时钟树、pinmux 和外设例程入手，不编造。

22在 STM32 上用 DMA 要注意什么？

参考答案：核对请求映射、方向、数据宽度、对齐及内存是否可达；确认正常/循环模式和中断处理。带 D-cache 的器件按手册处理 clean/invalidate 与 cache line 对齐，保证 DMA 使用期间 CPU 不改缓冲区。

23MCU 以太网开发按什么顺序排查？

参考答案：先看 PHY 供电、复位、MDIO、link 和速率，再排 MAC/DMA descriptor、缓存与对齐，最后检查 IP、ARP 和传输协议。先跑已知对端的 ping 或固定数据包，别一上来查应用。

24SDIO 或其他外设怎么说明验证？

参考答案：以 SD 卡为例，先按规范低速初始化、协商总线宽度和时钟，再压测读写并注入拔卡、CRC 错或超时。用返回状态、时序与重试计数定位层次，不把接入和性能测试混为一谈。

25STM32 有多片 RAM 时怎么安排数据？

参考答案：查芯片 memory map、大小及各总线主设备能否访问。用 linker section（链接段）放关键栈或 DMA 缓冲，备份存储另考虑掉电保持。最后查 map 文件和实际地址，再在板上验证外设能读写。

逐题参考答案

1WebSocket 遇到网络问题是否会重传？

参考答案：WebSocket 通常跑在 TCP 上：连接存活时 TCP 重传丢失的段并保持有序，不会让应用重新发送每条消息。断线后建立的是新连接，若要继续交付，需要消息 ID、应用 ACK、续传和幂等去重。

2TLS 的握手和数据加密分别做什么？

参考答案：以 TLS 1.3 为例，握手协商参数，用密钥交换和证书鉴别建立共享密钥；之后用派生的对称密钥与 AEAD 保护记录。不能把证书公钥描述为加密所有业务数据。客户端还要验证证书链和主机名。

3NV12 和其他 YUV 4:2:0 格式有什么差异？

参考答案：NV12 是 Y 平面加交错 UV 平面，NV21 则交错 VU；I420 的 U/V 是各自平面。8 bit 且无 padding 时平均 1.5 字节/像素，但实际还要看 stride、对齐和 plane offset。绿色花屏常需核查 UV 顺序与 stride。

4Opus 的压缩率、包时长如何估，跟 AAC 有何不同？

参考答案：用实际码率和对应 PCM 码率算压缩比；16 kHz 单声道 16 bit PCM 是 256 kbps，若编码 32 kbps 则约 8:1，未算封装。Opus 帧和包时长可配置，常见 20 ms，不是固定；AAC-LC 常见 1024 samples 一帧，时长随采样率变化。

5TCP 和 UDP 如何取舍？

参考答案：TCP 有序可靠的字节流，拥塞时可能因前面丢失而阻塞后续字节；UDP 保留数据报边界，默认没有重传、有序和拥塞控制。实时音视频可以接受部分丢失时常选 UDP 上的媒体协议；可靠控制则常用 TCP。

6用 trylock 避免死锁时，时延有哪些坑？

参考答案：拿不到第二把锁就主动释放已有锁可打破持有等待，但高竞争会活锁、饥饿或不断回退。优先建立全局锁顺序；若必须重试，要有上限、退避、超时或排队。测 P99 与最长等待，不只看平均值。

7MPP 配 H.264 时除 GOP 还要看什么？I 帧用帧间预测吗？

参考答案：同时确认码率控制、目标码率、帧率、profile、IDR 策略和输入像素格式。帧内预测利用同一图像邻域；帧间用参考图像与运动补偿。纯 I 图像不做帧间预测，但并非每个 I 图像都是 IDR。

8线程如何创建、传参并退出？

参考答案：pthread_create 接收入口函数与上下文指针；入口参数必须在线程读到前保持有效。运行中用同步机制协调，退出时先发停止条件并唤醒阻塞线程，再 join，最后销毁对象和 fd。

9多线程怎么防竞态？

参考答案：先列共享变量及写者；优先让线程独占状态并通过队列传消息。确需共享时用同一把 mutex 保护不变量，condvar 用谓词循环，独立计数可原子化。检查锁顺序和退出路径。

10互斥锁、自旋锁、读写锁何时用？

参考答案：mutex 等待时可阻塞，适合可能等待的普通线程；spinlock 忙等，只用于很短且不能睡眠的临界区；rwlock 可并行读，但频繁写或竞争时未必比 mutex 快。内核和 PREEMPT_RT 还要按实际锁类型与上下文选。

11write 成功返回 10，是否已经落到硬盘？

参考答案：普通缓冲写可能只复制到 page cache（页缓存），并不指示持久化。检查短写和错误，按需要用 fsync 或 fdatasync。若靠 rename 发布新文件，还要考虑父目录 fsync 和目标文件系统的语义。

12H.264 RTP 包太大，除了 FU-A 能怎么办？

参考答案：先按 MTU 减去传输头算 payload；可在编码器限制 slice/NAL 大小，适合的 NAL 直接封包。STAP-A 是聚合多个小 NAL，不是拆大 NAL；可用模式受协商约束，避免靠 IP 分片碰运气。

1316 GB 内存、512 GB 磁盘，能申请 1 TB 虚拟内存吗？

参考答案：先问 32/64 位、请求 API、进程资源限制、overcommit 和是否实际触页。64 位匿名映射可能只预留虚拟范围；不等于有 1 TB 可写物理后备，触页时可能被 OOM 处理。磁盘容量也不等于 swap。

14H.264 的 SPS 和 PPS 各保存什么？

参考答案：SPS 大体描述序列层的 profile、尺寸、参考帧与计时等约束；PPS 引用 SPS，给图像使用的熵编码、量化及其它配置。slice header 引用 PPS。初次解码必须获得跟该流匹配的参数集。

15文件级 static 为什么让其他源文件不能按名字访问？

参考答案：C 文件作用域 static 赋予 internal linkage，同一翻译单元能引用这个名字，其他翻译单元的同名标识符不会链接到它。变量的静态存储期与链接性分开理解；编译器优化还可能让符号不出现在成品里。

1字符设备从驱动代码到应用可访问，需要哪些步骤？

2module_init 做了什么？

参考答案：指定驱动的初始化入口。模块通过 modprobe/insmod 装载时调用；内建时通过 initcall（初始化调用）机制在启动中执行。入口通常注册 driver，而 probe 是设备匹配后对每个实例进行初始化，两者不同。

3initcall 在启动中起什么作用？

参考答案：链接脚本将带有 initcall 注册的函数地址放到指定段，内核按级遍历并执行。它解决内建组件初始化入口的登记与调度；可用 initcall_debug 看耗时，具体级别以对应版本源码为准。

4为什么 initcall 要分不同级别？

参考答案：早期基础服务要先准备，再启动依赖它们的子系统和设备。分级给出粗粒度依赖顺序，不能靠同级的偶然链接顺序解决所有依赖；设备资源未就绪可能用 deferred probe（延迟探测）。

5platform_driver 怎样匹配设备树中描述的设备？

6如果是在问 platform bus 的匹配优先级，顺序是什么？

参考答案：原帖未说明“优先级”的指向。以 Linux platform_match 为例，先检查 driver_override，再尝试 OF、ACPI、id_table，最后在没有 id_table 的情况下用名字。以目标版本源码为准，不能推广到 I²C 等其他总线。

7不靠现成 match，能定制匹配规则吗？

参考答案：设备模型的 match 是 bus_type 的策略，不是任意驱动都能替换已有总线的回调。自定义总线可以提供自己的 match；已有 platform bus 宜用支持的标准匹配和描述机制，probe 内可做硬件验证但那不是匹配规则。

8设备树自定义属性怎样让驱动识别？

参考答案：给属性设计具有厂商前缀的 binding，定义类型、单位与缺省行为，再用设备属性 API 或 of_property_read 读取。compatible 管匹配，自定义属性通常管配置。用 schema 和 dtbs_check 验证。

9如何把同一驱动构建成 .ko 或内建？

参考答案：在 Kconfig 用 tristate，Makefile 用 obj-$(CONFIG_FOO) += foo.o。m 输出模块并需按目标内核配置、符号版本编译；y 编入内核；未选中则不构建。分别查 .ko/modinfo 和实际启动日志。

10obj-m 与 obj-y 各指什么？

参考答案：obj-m 指定模块对象目标，随后由 Kbuild 生成可装载 .ko；obj-y 给当前目录聚合为 built-in.a，沿目录链接进入内核。多个源文件可组合成一个模块，不能把每个对象都当成独立可装载文件。

11相机驱动的工作可以按哪些层讲？

参考答案：按 sensor 控制、CSI 接收、ISP、vb2 队列到用户态说明。先交代你负责哪一层，再讲输入输出和错误处理。用 probe、media topology 和实际帧序号作为不同层的证据；没改过的厂商框架不要说成自己的工作。

12如何回答具体改动及验证？

参考答案：用“症状→证据→最小修改→回归”展开。例如明确改的是 sensor mode、时钟或数据链路，记录改前后的拓扑、帧号和错误计数。只讲实际改过的文件或接口，不照搬这篇帖子的履历。

13相机视频缓冲区怎么分配和使用？

参考答案：驱动常用 videobuf2 管队列，分配器按硬件能力选。应用 REQBUFS、QUERYBUF 和 mmap 后 QBUF，硬件填帧，DQBUF 交还应用。处理完再重新 QBUF；跨组件消费时必须确认旧数据已不再被读。

14视频流缓冲区需要哪些内存属性？

参考答案：重点是设备可寻址、plane stride/对齐、缓存一致性和容量。是否要物理连续取决于 DMA/IOMMU 和分配器；不能把 mmap 到的用户虚拟地址连续当成物理连续。缓存由 DMA API 管，不直接传 CPU 指针给设备。

15如何创建可跨设备流转的缓冲区？

参考答案：在支持的路径中用 DMA-BUF 导出或导入 fd，并约定格式、分辨率、stride、plane 和同步。fd 传的是共享资源句柄，不代表写入已完成；按队列完成事件或 fence 交接，消费者释放前不让采集端覆写。

16中断与线程要怎么交接和同步？

参考答案：硬中断先确认来源、必要时屏蔽或清状态，重活交给 threaded IRQ 或 workqueue。跨硬中断保护共享状态用允许该上下文的原语；再用 completion 或 waitqueue 唤醒普通线程，检查退出解绑次序。

17自旋锁与互斥锁怎么选？

参考答案：自旋锁对不可睡眠的短临界区合适，mutex 竞争可能睡眠，只能用于可睡眠上下文。涉及同 CPU 硬中断时须按场景使用 IRQ-safe 变体；PREEMPT_RT 的锁语义另核对。不要持自旋锁做阻塞 I/O。

18如何组织一个技术项目介绍？

参考答案：先讲输入、输出和约束，再只选一个自己真正负责的难点。给出为何选这个方案及对照证据，最后说已测边界和未测项。不要用整组结果冒充个人工作。

19如何判断两个无环链表相交？

参考答案：比较节点身份而非值。两个指针分别从两个头开始，走到尾后切换到对方头；走过 A+B 和 B+A 后消除长度差，在交点或 null 相遇。O(m+n) 时间、O(1) 空间；有环需要分情况。

const Node* intersection(const Node* a, const Node* b) {
    const Node* p = a;
    const Node* q = b;
    while (p != q) {
        p = p ? p->next : b;
        q = q ? q->next : a;
    }
    return p;
}
20怎么解释哈希表？

参考答案：哈希把 key 映射到桶，再按拉链或开放寻址处理冲突。负载因子决定常见探测成本，扩容时通常重散列；平均常数时间并不排除某些输入退化。相等的 key 必须得到一致的哈希。

21项目里什么时机会发生任务上下文切换？

参考答案：阻塞等待、主动让出、时间片到期或更高优先级任务变为就绪都可能触发，具体由系统策略决定。IRQ 进入内核本身不等于换任务；可结合调度 trace 证明是哪一次唤醒触发了切换。

22进程切换时调度器依据什么选下一个任务？

参考答案：先说明调度类与优先级，实时类的 FIFO/RR 和普通公平调度不同。普通调度还受内核版本、CPU 亲和性和负载均衡影响；较新 Linux 公平类采用 EEVDF 机制。不要把所有 Linux 一概说成轮转。

23堆和栈分别有什么特点？

参考答案：栈常承载调用帧，随调用返回自然回收，每个线程有自己的栈；动态分配对象通常来自堆，生命周期可以跨调用但要显式管理。参数不必上栈，大栈对象要防栈溢出；堆还要考虑碎片和分配耗时。

智元｜秋招二面
1I²C 协议的传输过程是什么？

参考答案：用 SDA/SCL 开漏和上拉，起止条件分别由 SCL 高时 SDA 变化定义。地址/数据按位传、每字节有 ACK/NACK；常见寄存器读需要 repeated START。先确认从机支持的地址与时序。

2Clock stretching（时钟拉伸）怎么工作？

参考答案：从机准备不及时可以把 SCL 继续拉低，主机释放后要等总线实际高电平再推进。并非所有控制器都支持相同伸展时长；超时要结合波形、数据手册和控制器行为处理。

3I²C 卡死通常由谁恢复？

参考答案：先确认谁拉低 SDA/SCL；若 SDA 卡低且 SCL 可控，主机可按规范或驱动能力发恢复时钟并生成 STOP。SCL 持续拉低不能硬靠九个脉冲解决，可能只能等、复位或隔离。从机不是这条通用恢复时钟的发起方。

4Linux I²C 子系统怎么分层？

参考答案：adapter 代表控制器总线，algorithm 描述传输方式，client 表示某个地址的设备，client driver 负责芯片实现。上层 i2c_transfer 经 core 调向 adapter 算法。不要把 adapter 和 sensor 的驱动混为一层。

5I²C 驱动的 probe 里通常做什么？

参考答案：获取电源、复位、GPIO/IRQ 和寄存器访问，核对芯片标识，配置默认状态，再向相应子系统注册。每个失败分支都要能清理，未就绪资源可延迟 probe，不把设备漏在线上。

6点云怎么预处理、滤波和分类？

参考答案：先按 ROI 和无效点过滤，按需体素降采样，再区分离群过滤与用 RANSAC 拟合地面等模型。分类依任务可按几何维度、聚类或学习模型。读原帖时“随机采样抑制”的具体算法未明确，面试先确认术语再答。

7如何说明视觉识别方案？

参考答案：说明输入格式、标定/预处理、特征或模型、输出和置信度。固定一批光照、遮挡和运动样本跑准确率与端到端时延；不要用模型指标代替系统端误差。

8移动机器人路径规划怎么说清楚？

参考答案：区分地图与定位、全局路径、局部避障及控制。给出地图表达、代价函数和可行运动约束，再测狭窄、动态障碍和定位漂移；具体算法按做过的内容展开。

9什么是内存踩踏，怎样定位？

参考答案：越界写、use-after-free 等可能破坏相邻对象，症状常晚于写入。最小化复现并启用 ASan 或配置相应内核检测，定位首个非法写。必要时用 watchpoint（观察点）定位具体访问。

10volatile 的作用边界是什么？

参考答案：对 volatile 对象的访问需要按语言规则保留，常用于 MMIO，但并不让读改写原子，也不保证跨线程同步或硬件顺序。内核 MMIO 优先按平台用 readl/writel 等；线程通信使用原子或锁。

11RTOS 的优先级反转怎么解决？

参考答案：低优先级任务持有高优先级要的锁，中优先级任务抢占低优先级时，高优先级反而久等。可用支持优先级继承的 mutex 或优先级上限，并缩短临界区；信号量并不一定提供继承。

12Cortex-M 的 PendSV 怎样协助 RTOS 切换？

参考答案：调度请求挂起低优先级 PendSV，等较紧急中断完成后保存当前任务上下文、更新当前 TCB，再恢复被选中任务。异常入栈和软件保存寄存器分工随 port 与 FPU 配置不同。

13CAN 仲裁怎么避免带宽被冲突破坏？

参考答案：节点同时发，在仲裁区逐位比较；显性位覆盖隐性位，发送隐性却读到显性的节点暂退，胜者继续，不破坏获胜帧。标准与扩展帧混合时还要考虑格式字段。

14CAN Bus-Off 是什么？

参考答案：发送错误计数达到控制器规范阈值会使节点退出总线。先查 ACK、位时序、接线与终端，再按协议、硬件与系统策略恢复；不要只循环 reset 掩盖故障。

15智能指针怎么选？

参考答案：单所有权用 unique_ptr；确需共享寿命用 shared_ptr；观察共享对象且不延寿用 weak_ptr，可打破循环引用。智能指针同步管理寿命并不自动使被指对象线程安全。

16DMA 用的内存有什么要求？

参考答案：DMA 设备需可访问的地址与布局，不保证与 CPU 虚拟地址相同。用 DMA mapping API 或适当一致性分配，检查 DMA mask、方向、对齐、scatter-gather 和所有权，完成前不要提前复用。

17DMA 与 CPU cache 怎么保持一致？

参考答案：非一致性平台可能出现 CPU 脏行没写回，或设备写完 CPU 仍读旧缓存。用 coherent allocation 或按方向 map/sync/unmap；即便缓存一致也可能需要内存屏障保证描述符写入顺序。

诺瓦星云｜嵌入式一面
1怎样介绍最有代表性的技术项目？

参考答案：从系统目标和个人负责范围入手，挑一个能展示日志、波形或基准的难点，说清根因、改动与回归。说明使用了哪些驱动接口，以及哪些是团队或厂商实现。

2驱动中怎么避免多个执行流同时操作 GPIO？

参考答案：保护的是整段不变量（如方向加电平顺序），不只是单次 API。访问会睡眠的 GPIO 用可睡眠上下文与 mutex；必要时转 threaded IRQ 或工作队列。统一控制者也能减少竞争。

3内核除了 mutex 还有哪些同步方式？

参考答案：按场景讲：spinlock 保护短且不可睡眠区，completion 用于一次事件，waitqueue 等条件，atomic 处理简单读改写，RCU 适合某些读多更新路径。先判断上下文和数据生命周期。

4spinlock 与 mutex 的主要区别是什么？

参考答案：mutex 竞争时可睡眠；spinlock 典型非 RT 内核中忙等，不能在持锁区调用睡眠 API。中断共享要选合适的 IRQ 变体；PREEMPT_RT 则按具体锁类型重新判断。

5原子操作的含义是什么？

参考答案：其他参与者从同步语义观察，它不可被拆成部分完成。例如原子加一是一个不可分割的读改写；atomic 不一定代表有完整排序，内存序和可见性要单独谈。

6举例说明哪个操作是原子的。

参考答案：atomic_fetch_add 对该原子对象是原子读改写，两个并发增量不会丢；普通 count++ 不具有这个保证。若要同时更新两个字段并保持和固定，仅分别用原子加减还不够。

7I²C 在 RK3588 板上出错，从哪些证据定位？

参考答案：看实际适配器驱动返回而非死背固定种数。常见有地址未应答 ENXIO、传输失败 EIO 或超时 ETIMEDOUT，具体映射看源码。对照供电、pinmux、地址、波形和 log 再定位。

8i2c_adapter 在 Linux I²C 的哪一层？

参考答案：它属于控制器适配层，对外代表一条可挂 client 的总线。其下是实际控制器或 bitbang 实现，其上有 core 和各个芯片的 client driver。

9适配器具体负责什么？

参考答案：总线编号、能力、算法回调和实际串行传输是适配器相关职责。core 对消息协调并调算法；同一适配器上的 client 通过地址区分。芯片寄存器协议仍属于 client driver。

10master_xfer 属于谁，单个设备用哪个结构体？

参考答案：设备实例用 i2c_client 表达；master_xfer 属于 adapter 的 struct i2c_algorithm，不是某个 client 的方法。client 通过 i2c_transfer 或 regmap 使用适配器执行消息。

11如何选 I²C 上拉电阻？

参考答案：需要在上升时间与器件灌电流之间取舍。总线电容、速率和电压限定最大电阻，低电平电压与吸电流限定最小电阻。用示波器量上升沿，不能用某个固定阻值适配所有板。

124.7 kΩ 和 10 kΩ 哪个上拉更强？

参考答案：相同电压下 4.7 kΩ 电阻更小，拉高更快，也需要器件在拉低时吸更多电流。选择仍看总线负载、上升时间和灌电流能力。

13GPIO 模拟 I²C，用什么输出模式？

参考答案：用 open-drain（开漏）或用输出低与切输入模拟释放，高电平靠上拉。不要推挽强驱高，否则会和从机 ACK 或 clock stretching 冲突；读 SCL 时也要考虑从机拉低。

14如何交代 U-Boot 移植版本与来源？

参考答案：说实际提交或 tag、主线还是 BSP 分支及增量补丁，并用 version、串口启动日志或版本锁定文件印证。不能确定就去源码和配置查，不随意说成官网最新。

15硬件 watchdog（看门狗）的原理是什么？

参考答案：硬件计时器倒计时，软件健康时按期喂狗；超时可以触发复位或其他配置动作。喂狗应受关键任务健康状态约束，不能由永远运行的线程盲喂；验证故障能触发并记录复位原因。

3TCP 为什么常说三次握手、四次挥手？

1RTOS 内核怎么运行，信号量与互斥锁怎么选？

参考答案：调度器管理就绪与阻塞任务，时钟和事件可以唤醒任务。信号量常用于计数或事件，mutex 具有持有者语义且某些实现支持优先级继承；ISR 不应拿会阻塞的锁。

2RTOS 怎么安排任务优先级？

参考答案：按周期、deadline 和运行预算选，关键任务高优先但要短。把日志和慢 I/O 降优先级，限制持锁时间。是否同优先级轮转或动态调度要看内核配置。

3中断在 RTOS 内怎样发生和延后处理？

参考答案：硬件 IRQ 先打断当前执行，ISR 确认来源并处理必要状态，可唤醒任务继续做重活。所谓软中断应先确认是软件触发异常、PendSV，还是软件 deferred work，不同实现不能用同一套规则。

4RTOS 有硬中断来时系统怎么处理？

参考答案：CPU 按中断向量和优先级进入 ISR，保存规定上下文。ISR 清硬件状态并按 RTOS 可用 API 交付数据；退中断时若需抢占可切换。不能从高于系统调用上限的 IRQ 随意调用内核。

5两个软件触发的事件同时发生怎么办？

参考答案：先问平台。对 NVIC pending 异常按优先级和挂起条件处理，可能 tail-chaining；对任务中的软件事件则按队列和调度策略。测试要覆盖同优先级和未能及时消费。

6RTOS 通常运行在什么处理器上？

参考答案：常见 MCU，例如 Cortex-M 或 RISC-V MCU，也可运行在应用处理器。关键是移植层支持寄存器保存、中断控制和时钟；不应把 RTOS 与某一种 CPU 绑定。

7I²C 主机及从机地址怎么理解？

参考答案：从机地址常由芯片固定值、绑带或寄存器决定；主控发事务时选择目标地址，不需要先给普通 controller 分配被寻址 ID。若控制器还支持 target 模式，才另有本机 target 地址。

8热接入 I²C 从机后会自动交换地址吗？

参考答案：经典 I²C 不会像 USB 自动枚举；主机要知道地址及设备协议，热插拔还需硬件支持和总线电气设计。特殊协议的动态地址分配不能泛化。必要时检测地址冲突或引入 mux。

9UART 通常接哪些线？

参考答案：双向 TX、RX、GND；只单向通信可省去不使用的数据线，硬件流控可需 RTS/CTS。先匹配电平，共地与地偏移要考虑。

10如何把板上 UART 接口用到实际设备？

参考答案：UART 给出串行收发时序，物理接口可由 TTL/CMOS、RS-232 或 RS-485 等收发器实现。别用裸 MCU 引脚直接接不兼容标准；先查驱动能力和电压。

11RS-232 与 RS-485 电气上差在哪？

参考答案：RS-232 以相对地单端电压表示逻辑，RS-485 是差分，由两线相对电压判定。接收阈值与允许共模范围看标准和收发器，A/B 标签存在厂商差异，不能只背端子名字。

12Linux 驱动绑定最关键的数据结构和阶段是什么？

参考答案：设备对象、驱动对象与 bus_type 的 match 使它们关联；match 成功调用 probe。模块装载只登记驱动，不自动证明有实例。查 sysfs 的 driver 链接、日志和实际 I/O。

13Linux 下 I²C 设备怎么挂驱动？

参考答案：控制器注册 adapter；设备树在它下面描述 client 地址、compatible 与资源；驱动匹配后 probe；最后通过所属子系统暴露用途。核对 DT 与设备实际地址，而不是仅看模块是否存在。

14SPI 编程题涉及误差和复杂度，怎么准备？

参考答案：汇编没给公式及输入约束，不能还原算法。遇到类似问题先定义误差为绝对、相对或累积截断误差，再给基线复杂度、可复用中间值和边界对照。

3可执行文件各段最后放在 ROM 还是 RAM？

1SPI 线上一笔传输怎么走？

参考答案：主控拉有效片选并供时钟，双方按 CPOL/CPHA 的采样边沿收发。全双工时每个时钟两方向都有位，读寄存器可能需 dummy 字节；按手册看片选是否跨段保持。

2PID 三项分别改善什么？

参考答案：P 按当前误差反应，I 积累误差改善稳态偏差，D 反映变化率可抑制振荡但放大噪声。实现时要管积分饱和、采样周期和导数滤波；用阶跃响应调参。

3C 二维数组在地址上连续吗？

参考答案：真正的 T a[R][C] 是连续保存的行数组，行内连续，按 sizeof(T) 与列数决定偏移。T** 指向的多行可以各自分配，不同布局。

4手写合并两个升序数组。

参考答案：双指针每次选当前较小项，任一路耗尽复制另一侧剩余，时间 O(m+n)。若目标是第一数组预留空间，改从末尾选较大项原地写，防覆盖尚未读元素。

5SPI 与 CAN 工作原理有何区别？

参考答案：SPI 是片选和时钟驱动的短距串行链路，常见单主；CAN 是差分共享总线，使用位仲裁、错误帧和重传机制。分别按速率、节点数、距离与错误处理选型。

6Linux 中进程和线程区别是什么？

参考答案：线程通常共享地址空间和文件，独立栈与寄存器；进程隔离通常更强。都可被调度，线程共享不等于不需要同步。

7匿名管道、命名管道和信号量怎么选？

参考答案：匿名 pipe 常用于有关联的进程用继承 fd 通信，有名 FIFO 可让独立进程通过路径打开，两个都是字节流。信号量用于同步或计数，不直接搬运报文。

参考答案：AE（自动曝光）、AWB（自动白平衡）、AF（自动对焦）。分别控制亮度、色彩中性与焦点；硬件没有可调光圈或对焦机构时，相应能力有限。

15画面过曝怎么调？

参考答案：降低曝光时间或增益，支持可变光圈时也可收小光圈；先看直方图、高光饱和与场景。运动要权衡拖影，灯光要考虑频闪，用相同场景对照。

16是否总应该先调光圈？

参考答案：不一定。固定光圈机型不能调；可变光圈也要同时考虑景深、运动和噪声。视频常先设合适快门区间，再让 AE 在硬件允许的参数中选。

17CMOS 成像与滚动/全局快门有什么关系？

参考答案：像素积分进光再读出。rolling shutter 逐行曝光或读出时序错开，运动可能倾斜；global shutter 同时曝光更利于动作。曝光时间、增益和满阱都影响噪声与动态范围。

18EV 是不是增益？

参考答案：不是。EV（曝光值）描述曝光设置的组合；EV compensation 是让自动曝光目标偏亮或偏暗，常以档为单位。增益只是相机可能调整的一个变量。

19RGB、YUV 以及 NV12 该怎么区分？

参考答案：RGB 用三色表示，视频常用 YCbCr 的亮度和色度分量。4:2:2 水平减半，4:2:0 水平垂直都降采样；NV12 是 Y 平面加 UV 交错。H.264 是编码、MP4 是容器，别和像素布局混用。

20为什么可以减少色度采样？

参考答案：视觉对部分空间亮度细节比色度更敏感，色度降采样可减少带宽。代价是色边或文字变糊；需区分色彩矩阵、量化范围与采样方式。

21Android 相机栈相对于 Linux 多了什么？

参考答案：Android 在 Linux 驱动之上还有 Camera framework、service 和 HAL 等。应用通过平台 API，HAL 将请求、元数据与缓冲区映射到厂商实现；不是应用直接控制 sensor 寄存器。

22Android Camera HAL 是哪一层？

参考答案：它是 Android framework 与设备厂商相机实现之间的接口，接收拍摄请求、传递结果和缓冲。驱动负责底层资源和数据路径；讲具体版本时核对 AIDL/HIDL 接口。

1xv6 如何分配物理页？

参考答案：标准 xv6 使用 kalloc/kfree，以空闲链表管理物理页，典型大小 4 KiB；用户页需通过页表映射。多核锁实验可改为每 CPU freelist 并在不足时借页。不要说它用 Linux vmalloc 分配页。

2Lazy allocation（惰性分配）如何实现？

参考答案：扩展虚拟尺寸时不急着分配物理页。访问有效的未映射区时 page fault，内核验证地址与权限、分配清零页并映射，再回到用户，越界则拒绝。处理 copyin/copyout 和 unmap 时也要考虑空洞。

3COW（写时复制）如何实现？

参考答案：fork 初始让父子共享物理页并标记 COW/只读。写 fault 时检查标记，必要时复制新页并更新 PTE、引用计数与 TLB。只读代码页不能被错当成 COW 写入；copyout 也要保证不会写共享页。

4惰性分配的开销与优化点是什么？

参考答案：少用的地址不浪费物理页；大量连续首次访问则可能为每页触发异常。可以按工作负载评估批量预分配或局部性策略，比较缺页次数与额外驻留页。不要把文件 readahead 直接等同匿名页分配。

5定时器回调实验如何返回用户态执行？

参考答案：累计用户 CPU tick，触发时保存用户 trapframe，令恢复的 PC 指向回调，并防止回调重入。回调结束经 sigreturn 恢复寄存器和 PC。不应把用户函数在内核中直接调用。

6xv6 实验环境的物理内存怎样确定？

参考答案：不是 ISA 常量。以使用的 QEMU 命令行、memlayout 和内核初始化为证据，区分配置总容量与内核可分配范围。不要背候选人的环境数字替代自己的设置。

7Sv39 的虚拟地址如何分解？

参考答案：三级页表，各级索引 9 位，页内偏移 12 位，逻辑有 39 位；高位按规范做符号扩展。xv6 还会定义自身采用的用户地址上界，不能把架构范围等同进程可用上限。

8标准 xv6 有 swap 吗？

参考答案：标准教学版不把用户页自动换到磁盘；惰性分配或 COW 也不是 swap。若自己实现，需有页替换、磁盘后备、页表状态与 fault 恢复，并验证 I/O 错误和并发。

9TCP 连接状态机怎么设计？

参考答案：依据事件和当前状态迁移，例如 SYN_SENT、ESTABLISHED 和各关闭阶段；状态与序列号、重传定时器关联。明确被动和主动关闭、重复报文、非法标志，再用 RFC 和分步轨迹核对。

10TCP 快速重传怎么理解？

参考答案：经典 TCP 可根据重复 ACK 推断缺段，在超时前重传；具体阈值、SACK 或现代算法看实现。它不同于 RTO 超时重传，测试应覆盖丢包、乱序及重复 ACK。

11TCP 状态机怎么测？

参考答案：用表驱动用例给定初态、报文、期望输出和终态。覆盖握手、重复、重传、半关闭、超时和异常标志；推进虚拟时钟，避免测试取决于睡眠时长。

12用 JUCE 怎样实现可拖拽的音频缩略图？

参考答案：把缩略图峰值数据和绘制解耦，按单位区间聚合，不在 UI 循环重复扫原 PCM。拖拽把像素映射到时间与样本范围，更新选区并局部重绘；音频线程不做阻塞的 UI 操作。

13手写：给出出现频率最高的 k 个元素。

参考答案：用哈希表计数，维护大小 k 的小根堆，遇到更大的频率替换堆顶。设不同元素 m 个，时间 O(n+m log k)，空间 O(m+k)。也可用按频率分桶；先说明并列是否有约束。

9手写：求字符串每个位置到最近目标字符的距离。

参考答案：从左扫，记录最近一次见到目标字符的位置，给右侧元素算左边距离；从右扫同理，逐位与左侧结果取最小。例：字符串 aaabaa，目标 b，输出 [3,2,1,0,1,2]。目标保证存在；时间 O(n)，除输出外 O(1)。

std::vector<int> shortestToChar(std::string_view s, char c) {
    const int n = static_cast<int>(s.size());
    std::vector<int> d(n, n);
    int last = -1;
    for (int i = 0; i < n; ++i) {
        if (s[i] == c) last = i;
        if (last >= 0) d[i] = i - last;
    }
    last = n;
    for (int i = n - 1; i >= 0; --i) {
        if (s[i] == c) last = i;
        if (last < n) d[i] = std::min(d[i], last - i);
    }
    return d;
}

2为什么要选原帖说的 React 模型？

参考答案：先问 React 是 UI 框架还是 Reactor I/O 模式。如果是 Reactor，少量事件循环处理 I/O 就绪，耗时工作交给有界线程池；优势是连接数上升时避免一连接一线程，代价是不能堵住事件循环。如果是前端 React，则从组件状态与更新设计说。

3哪些资源共享，怎么避免线程互相踩数据？

12SPS/PPS 动态插入通常指什么？

参考答案：指按启动、重连或参数变化将匹配参数集适时发送，不是每帧拼固定字节。可放在 IDR 前做带内刷新，或由容器/信令提供配置。确保 slice 引用正确 PPS、PPS 引用正确 SPS。

13IDR 如何帮助接收者独立起播？

参考答案：IDR 阻断后续对该点之前图像的引用，但解码侧仍需完整 IDR 和匹配的参数集。对新解码实例对照“只有参数集”“只有 IDR”“两者齐备”，要先排除容器已外带配置。

14H.264 码流有哪些组成？

参考答案：用 NAL 单元组织 VCL 切片与非 VCL 参数集、SEI 等。Annex B 用起始码分隔，某些容器用长度前缀并单独存配置。NAL 不是网络包也不总等于一帧，转换和分片时不要混。

15H.264、H.265、AAC 和 MP4 分别属于哪一层？

参考答案：前两者是视频编码，通过预测、变换、量化与熵编码提高压缩率，H.265 的块与编码工具不同。AAC 是音频编码，MP4 是容器，能复用音视频轨、配置、时间戳与索引。不要用文件扩展名推断编码。

16FFmpeg 编解码常用哪些步骤和 API？

参考答案：解复用读 AVPacket，解码 send_packet 后循环 receive_frame，编码 send_frame 后循环 receive_packet，再复用输出。send 返回 EAGAIN 时先取输出再重送未接受输入；末尾送空输入并排空。时间戳要换算 time base。

17手写：如何构造严格小于 n 的最大合法整数？

参考答案：原帖没给数字集等完整约束，先确认合法数字能否重复、前导零及无解返回。若给定数字集且可重复，从最高位试最大可行数字；相等就继续，失败回退找更小位并让后缀取最大。没有同长度解再试短一位。

逐题参考答案

一面
1指针和数组在 C 里有什么不同？

参考答案：数组是固定数目的同类型元素，指针变量存地址。很多表达式里数组会衰变成首元素指针，但 sizeof、取整个数组地址等场景不衰变；函数形参 int a[] 会调整成指针，要额外传长度。

2typedef 和 #define 有什么区别？

参考答案：typedef 是编译器处理的类型别名，有作用域而不建立新类型；宏是预处理 token 替换。typedef int* P; P a,b 两个都是指针；宏展开声明 int* a,b 则 b 是 int。这个例子直接看出区别。

3结构体与联合体怎样布局？

参考答案：struct 的各成员各有存储并可能插入 padding（填充）；union 成员共用存储，大小至少容纳最大成员并满足对齐。协议解析不应依赖结构体直接映射字节；union 与类型重解释还要按语言规则判断。

4野指针和悬空指针分别是什么？

参考答案：野指针通常指没有初始化成有效值的指针；悬空指针曾合法，但对象已释放或已超出生命周期。两者都不能解引用。例如返回局部数组地址和 free 后访问分别是典型生命周期问题。

5怎么避免野指针和悬空指针？

参考答案：初始化，建立唯一清楚的所有权约定，检查借用是否活得比对象短。free 后清空当前指针不能清除别处的别名。C++ 优先 RAII 与 unique_ptr，真正共享才用 shared_ptr；用 ASan 测错误路径。

6C 程序在 Linux 进程里的常见内存区域有哪些？

参考答案：常见有可执行映射、共享库、堆或 mmap 分配区、各线程栈及内核不可访问的用户边界。地址布局受 ABI、ASLR 和平台影响，可看 /proc/PID/maps；不是 C 标准规定的固定地址顺序。

7.text、.rodata、.data、.bss 各放什么？

参考答案：常见 ELF 中 .text 是指令，.rodata 是只读数据，.data 是带非零等初始化数据，.bss 表示启动时清零的存储，文件不必存齐零字节。最终加载按 program headers（程序头）而非只看 section 名字。

8动态分配区和调用栈怎么区分？

参考答案：调用栈存帧、保存寄存器和部分局部变量，跟线程及函数调用绑定。堆式分配由 allocator 管理，可跨调用生存，需释放。大数组别默认放栈；嵌入式还要查峰值和栈高水位。

9C / C++ 源文件怎么变成可执行文件？

参考答案：预处理展开头文件和宏，编译做检查与优化并生成目标相关表示，汇编产生目标文件，链接解析符号并重定位。可用 gcc -E、-S、-c 分步观察。未定义引用常在链接时暴露，不等同语法错误。

10Linux 的进程和线程如何区分？

参考答案：进程通常有独立虚拟地址空间与资源边界；同一进程的线程通常共享地址空间、打开文件等资源，各有寄存器、栈和调度实体。共享内存让通信方便也带来数据竞争；线程间仍需同步。

11IPC（进程间通信）有哪些做法？

参考答案：管道传字节流，Unix 域套接字支持请求和传 fd，共享内存适合大块数据但需要另外同步。信号适合通知不适合大量数据，消息队列保留消息边界。按吞吐、复制和故障恢复选。

12线程调度和上下文切换怎么讲？

参考答案：从可运行、阻塞、唤醒讲起：调度器按调度类、优先级及策略选任务，切换保存与恢复上下文。Linux 的 schedule 与 Cortex-M RTOS 的 PendSV 是不同实现，不混起来报。用等待 I/O 被唤醒的例子说清时间点。

13H.264 码流大致是怎样生成和组织的？

参考答案：编码器用帧内或帧间预测，编码残差的变换、量化结果和预测信息，再做熵编码。NAL 携带切片或参数集；I/P/B 描述预测方式，IDR 是随机访问和切断参考的一种关键边界。

14怎样讲一个实习技术项目而不流水账？

参考答案：点出约束、数据路径和自己负责的接口，再挑一个真实故障，说日志、根因、改动与回归。面试若偏用户态，补从 fd 到线程消费的路径；涉及内核的部分用公开接口讲清边界。

15移植 LVGL 时你具体会接哪些接口？

参考答案：先说明有没有亲自移植。按 v9 举例：初始化 display（显示对象）、分辨率、draw buffer（绘制缓冲区）和 flush callback（刷屏回调），传输完成才调用 lv_display_flush_ready；再接 input device、tick 和周期性 lv_timer_handler。先跑纯色、触点和连续重绘；v8 API 名字不同。

16用 LVGL 做项目时，有什么技术内容值得讲？

参考答案：挑一个真实界面，讲对象树、控件事件、数据怎么进入 GUI 线程，以及怎么防止刷新卡顿。只能说到能展示的部分；没有实机移植就区分应用层 UI 编写和板级 display/input 接入。

17怎样缩小 Bootloader 体积？

参考答案：用链接 map 和 size 先找体积大户，再分项删日志、功能或标准库依赖，考虑 section GC 和 size 优化选项。保留签名、异常向量与升级回退，最终看镜像能否放入分区并验证冷启动、恢复和升级。

18移植平台不同会改动什么？

参考答案：不用背候选人板号。说清真实硬件的 CPU、Flash/RAM、启动方式和 BSP 边界；迁移时核对时钟、向量表、地址映射和 linker script，再验证烧录、复位和故障回退。

19低功耗做了哪些层面的优化，如何测？

参考答案：先用电流仪量活动、休眠、唤醒时序和占空比；软件侧关不需要的时钟/外设、批处理工作以延长睡眠；硬件侧查上下拉、稳压器静态电流与调试器漏电。量一个完整周期间能耗，不只看最小电流。

20怎样介绍 Linux 子系统相关工作？

参考答案：按硬件或内核子系统、用户态接口、事件路径和系统选型讲真实部分。如果只调用已有 API，就说集成方式与验证，不把它包装成编写了整个子系统。

3项目里的 UI 部分怎么实现？

4接触过哪些 UI 框架，如何比较？

10遇到难定位的问题怎么展示排查？

11项目中的另一款操作系统如何与 Linux 比？

参考答案：先确认具体系统和版本，别将“国产”当内核架构。按调度、地址空间、驱动模型、IPC 和工具链比较，再说在真实项目上用了哪项能力。没有测过的实时性不给数字。

12不同操作系统可以如何分类？

参考答案：从应用约束开始分：通用 OS 强调多进程隔离和资源管理，RTOS 强调可预测响应，裸机没有 OS 调度。类别并不互斥所有特征；Linux 可配置实时增强，某些 RTOS 也有 MPU 或用户隔离。

13了解 FreeRTOS 与 µC/OS 的哪些部分？

参考答案：可先讲任务、调度、队列、互斥和 ISR 路径，再说明接触的是哪个版本和移植层。只在 FreeRTOS 做过的东西标明，不把 API 当另一系统的行为。

14FreeRTOS 和 µC/OS 如何比较？

参考答案：具体对比 FreeRTOS 与 µC/OS-II 或 III；它们的任务优先级约束、同优先级调度、内核对象 API 和配置会随版本不同。同一业务要比较最坏时延、移植成本和许可证，不只背“都是实时系统”。

15已经有 TCP 还需要 RS-422 吗？

参考答案：两者不在同一层：TCP 是传输层可靠字节流，RS-422 是差分串行电气接口。项目可能用 TCP 做联网而用 RS-422 接现场外设。说明链路距离、抗干扰、已有接口和协议，而非比较谁能“替代”谁。

16为什么在某串行链路选 RS-422 而非 RS-485？

参考答案：先问拓扑、收发方向、线对与既有设备。RS-422 常用于一驱动多接收的差分链路；RS-485 支持多驱动共享总线，常见二线半双工，也可四线。总线仲裁、终端和方向切换要按协议与设备定。

17RS-422、RS-232、RS-485 的主要差异是什么？

参考答案：RS-232 是单端，常见点对点；RS-422、RS-485 都是差分。RS-422 常见单驱动多接收，RS-485 支持多驱动但同一共享线对需避免同时发送。UART 提供串行时序，Modbus 等上层协议提供报文语义。

18怎样说明给 LVGL 或 Ultralytics 提交的 PR？

参考答案：以可追溯改动为主：对应 issue、复现条件、选择的修复点、回归用例和 PR 状态。文档、配置、功能代码区别讲，提交不等于已合并；没有真实 PR 不套作者经历。

19如果继续深挖 LVGL 贡献，要准备什么？

参考答案：准备版本、涉及的模块、关键函数、发生错误的数据或事件流、修改后为何安全，以及测试覆盖。若改动涉及屏幕刷新，可说明 flush 的生命周期；没改过底层就不声称移植了驱动。

20H.264 和 H.265 有什么核心区别？

参考答案：都有预测、残差变换、量化和熵编码；H.265/HEVC 采用 CTU 等不同分块及预测工具，通常同等主观质量下可用更低码率，但算力、兼容性与延迟要实测。别承诺固定节省比例。

21如果只熟 H.264，如何展开讲得有深度？

参考答案：从 NAL、SPS/PPS、I/P/B、IDR 和参考关系讲到实际黑屏或重连。用相同码流做有无参数集与 IDR 的对照，区分编码、裸流格式、容器和网络封包。对 H.265 不熟就标明。

22I²C、SPI、UART、ADC、DMA、CAN 各是什么？

参考答案：I²C 是寻址共享开漏总线，SPI 是时钟同步并靠片选，UART 是异步串行，CAN 是带仲裁和错误管理的总线。ADC 将模拟量量化为数字，DMA 搬运数据；后两者不是串行协议。可各说一个典型受限场景。

23DMA 的全称和作用是什么？

参考答案：Direct Memory Access（直接内存访问），让 DMA 控制器或设备在配置后搬运数据，不必 CPU 逐字节复制。CPU 仍负责描述符、同步、完成处理和错误；设备地址、缓存一致性与复用时间必须明确。

24Qt 多线程有哪些常用写法？

参考答案：可用 QObject worker + moveToThread 加事件循环，短 CPU 任务可用线程池或 QtConcurrent。跨线程 queued connection 将事件送到接收者所属线程；GUI 对象留在主线程。退出先通知停止，再 quit/wait 和按线程亲和性析构。

25内存泄漏、野指针、悬空指针如何区分与排查？

参考答案：泄漏是资源该释放却未释放；野指针没有初始化成有效指针；悬空指针指向已经结束生命周期的对象。C 用显式所有权及清理路径，C++ 用 RAII，配合 ASan/LSan 或 Valgrind 检测不同类型错误。

26项目中 C++ 适合哪些场景？

参考答案：C++ 适合用 RAII 管 fd、线程和缓冲，用类型表达 ownership；C 常见于内核接口和某些裸机库。跨 C ABI 时约定结构与生命周期；优先用真实模块和工具链约束解释，不把语言选择说成绝对规则。

2怎么用 GDB 调试 Linux 内核？

参考答案：保留匹配 vmlinux 和调试符号，在 QEMU gdbstub 或配置好的 KGDB 连到运行目标。确认符号、地址随机化及模块加载地址，一步步断点；真实板上暂停 CPU 会改变时序，不能据此直接量延迟。

3怎样用 GDB 辅助定位内存泄漏？

参考答案：GDB 可对嫌疑分配、释放下条件断点，比较调用栈和对象持有者，但不是自动泄漏检测器。内核可先用 kmemleak（需配置）定位疑似未引用对象，再做重复复现与定点验证；工具输出不是最终结论。

4内存为什么会泄漏？

参考答案：常见于错误分支没有释放、指针被覆盖、引用计数没归零、取消任务漏回收。先定义谁拥有对象，再覆盖成功、失败和退出路径；反复运行后看分配/释放差值是否持续增长，并区分正常缓存。

5循环剪枝和内存池复用各怎么做？

参考答案：剪枝利用不变量跳过不可能改善结果的迭代，并用边界与随机样本比较正确性。池化把固定大小对象预分配，通过 free list 复用以降低分配开销；释放时检查重复归还，池耗尽要有明确策略。两项分别做消融。

6怎么证明单次运行缩短了约三成？

参考答案：用同一输入、构建参数、机器与负载，对改前改后做预热和多次测量。报告中位数和尾部以及单位；相对减少为 (基线−新值)/基线，区别于吞吐倍率。用 perf 或分配计数说明为什么变快，同时确认输出一致。

7怎么管理内存池以改善缓存局部性？

参考答案：固定大小对象可在 slab/连续块中管理，使经常一起访问的数据靠近；热点字段紧凑，跨线程写入避免 false sharing。free list、对齐和缓存行隔离有空间成本。用访问模式与 cache-miss 指标证明效果。

8选 RISC-V 平台时通常考虑什么？

参考答案：先交代架构、SoC 与板卡不是同一个概念；看现有工具链、调试、外设和学习目标。可说开放 ISA 便于阅读启动与异常路径，但不能据此保证板上 IP 或 BSP 也开放。

9RISC-V 芯片的系统总线如何确认？

参考答案：ISA 不规定 AXI、AHB、APB 等片上互联。查看目标 SoC 框图、IP 地址图与 RTL/文档，说明 CPU、内存、桥和外设经过的路径。若只有模拟器也要分开说。

10UART 驱动如何确认用的是哪个 IP？

参考答案：查手册与 live DT 的 compatible，跟到匹配的驱动或固件配置，再用寄存器表和中断行为交叉核对。比如 8250 兼容与其他 UART 不能仅凭波特率或 /dev 节点名字判定。

11Linux 里常用哪些诊断命令，怎样给例子？

参考答案：按故障而非背清单：设备未出现看 dmesg 和 sysfs，线程卡住看 ps/top 与 /proc，网络不通看 ip/ss。说清每个结果能排除什么，区分发行版工具和内核特性。

12Linux 网络怎么配置和定位？

参考答案：先检查链路与接口，用 ip addr 和 ip route 查地址、掩码与路由，再验证 ARP/邻居、网关和 DNS。临时配置与 NetworkManager/systemd-networkd 等持久配置分开，改完重启验证。

13Linux 从启动到服务运行经过什么？

参考答案：固件/Bootloader 交给内核，内核初始化并挂载根文件系统，启动 PID 1。以 systemd 为例，它按 unit 依赖启动服务；检查内核日志、systemctl status 和 journalctl，分清服务失败与内核未启动。

1手写：把二叉树展开成先序顺序的链表。

参考答案：迭代时遇到左子树，找它沿右指针走到的最右节点，把原右子树接上，再将左子树移到当前节点的右边，清空左指针，继续沿右边走。O(n) 时间、O(1) 额外空间。检查空树、全左链、全右链。

void flatten(TreeNode* root) {
    for (auto p = root; p; p = p->right) {
        if (!p->left) continue;
        auto tail = p->left;
        while (tail->right) tail = tail->right;
        tail->right = p->right;
        p->right = p->left;
        p->left = nullptr;
    }
}

7static 在 C 和 C++ 中有哪些意义？

面试前先练这三件事

讲一个项目，90 秒。 用「问题 → 自己负责的部分 → 一个难点及证据 → 验证结果」讲。只报亲自测过的数字；没测就说准备怎么测。

画一条 Linux 驱动链。 从设备树匹配和 probe 讲到驱动注册、设备节点、应用 open/read。准备解释在哪看日志，怎么区分未匹配和通信失败。

演练一次故障定位。 选 I²C 无应答、串口丢帧或传感器时间戳不同步之一，讲清复现、观察、排除、改动、回归五步，再补一个你能讲清取舍的同步机制。
