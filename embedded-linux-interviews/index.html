嵌入式 Linux 实习面经

面向嵌入式 Linux 实习与校招备考，覆盖驱动和 BSP、音视频、并发与操作系统、车载通信。面经为候选人复盘，不代表同团队会问同一套题。

题目与参考答案

怎么用： 先读「原帖题目要点」，再用「参考答法」口述。题目是按原帖转述，不冒充现场原话；答案是备考参考，不是发帖者原答。原帖未公开具体问法的标为「自练追问」。

实习面经 · 系统设计

影石一面约 50 分钟：项目链路、端侧部署与性能

原帖题目要点： 从采集、控制到上报如何设计？为什么选这个模型、效果不佳怎么查？Linux 进程 CPU 90% 怎么定位？C 内存拷贝与深浅拷贝。

答 1｜如何在 90 秒介绍采集与回放项目？ 先讲需求，再按采集、编码、存储及回放画数据流，指出各模块之间的接口和数据所有权。以有界队列解耦采集与写盘为例，说明队列满时选择阻塞还是丢弃，以及断网时是否能本地继续录制。最后说明如何用长时间录制、丢帧统计和文件完整性校验验证设计，只报告实际测过的结果。

答 2｜模型选型与诊断。 先明确离线转写、视觉理解等任务的约束，再用固定样本衡量准确性、端到端耗时和峰值内存。效果差先核对输入与预处理，再逐项隔离模型、量化、推理后端和后处理。没有做过同条件对比就说明准备怎么测。

答 3｜CPU 高怎么查？ 确认占用是持续还是瞬时，以及百分比按单核还是全机计。用 top -H -p PID 找热点线程，设备支持时用 perf 采样调用栈；不支持则看 /proc 的线程统计并给流水线各段打点。按证据分辨忙轮询、反复拷贝、软件编解码或内核开销。用同样的输入、相同负载对比改前改后的 CPU、延迟与掉帧。

答 4｜拷贝如何区分？ 浅拷贝可能只复制地址，深拷贝复制资源并建立独立所有权。非重叠字节区用 memcpy，可能重叠用 memmove；不能用 memcpy 通用地复制含非平凡成员的 C++ 对象。C 字符串还要检查容量并保证终止符。

实习面经 · 并发与基础

影石相机实习：结构体、线程安全与手写代码

原帖题目要点： 共享变量和 count++、函数栈、结构体传值／指针、父子类同名字段、static、哈希表与判环。

答 1｜并发自增。 两线程无同步地读写普通变量构成 C++ 数据竞争，行为未定义，不只是丢更新。独立计数用 atomic；多个字段必须一起保持一致时用互斥。讲有界队列时说清生产者、消费者、满队列的策略及退出唤醒；条件变量用谓词等待。只把你能指出实现的策略说成已做。

答 2｜栈与所有权。 栈帧的寄存器保存、局部变量和对齐由 ABI 与编译器决定；参数不一定上栈。结构体传值语义上是副本；指针指向原对象，要保证其生命周期。C 的文件作用域 static 限制链接性，函数内 static 改变存储期；C++ 派生类同名成员隐藏基类成员，可显式限定 Base::a，不是动态分派。

答 3｜哈希与判环。 哈希冲突可用拉链或开放寻址；平均代价受分布与负载因子影响，最坏可退化。链表判环用快慢指针，快两步慢一步；快指针无法前进则无环，相遇则有环。O(n) 时间、O(1) 空间。

bool hasCycle(const Node* head) {
    const Node* slow = head;
    const Node* fast = head;
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return true;
    }
    return false;
}
实习面经 · 项目与通信

经纬恒润实习：项目分工和排查证据

原帖题目要点： 追问科研思路、项目具体分工、处理顺序和解决办法，未公开逐道技术题。

自练追问｜设备断网后连不上，怎么定位？ 假设一个设备联网后反复掉线，先记录触发条件和各层日志，再区分物理链路、地址配置、网络可达性与应用超时。找到根因后用正常和异常场景做回归。若追问断线重连设计，可以用单一状态机管理连接、超时、退避与取消，避免多个线程重复发起连接。这是模拟题，不是原帖披露的面试题。

实习面经 · 项目与通信

Momenta 实习：UART、CAN 和车载诊断

原帖题目要点： 驱动分层与应用接口、ADC/PWM/DIO/CAN 验证、CRC、UART 与 DMA 错误、CAN Bus-Off、OBD 和诊断下载流程。

答 1｜串口偶发错误怎么排？ 先确认电平、接地和波特率／校验位；再看 overrun、framing 和 DMA 错误计数及环形缓冲区读写位置；最后验证帧头、长度、CRC 和超时重同步。用固定帧回放并同时留波形和字节流。

答 2｜CAN 如何判断故障？ 区分 ACK 错误、位错误和 Bus-Off。ACK 错误先确认其他节点能正确接收并应答，检查位速率、接线和终端匹配。Bus-Off 要按控制器和系统策略恢复，并记录错误计数和恢复结果。CRC 是检错，不是纠错。若没做过 UDS，可讲诊断会话、前置检查、按块传输、完整性校验与失败回退的设计思路，不把它说成自己的项目。

实习面经 · 驱动与 BSP

影石驱动实习：设备树、字符设备、I²C 与 IRQ

原帖题目要点： I²C 工作过程、设备树、驱动注册、设备节点与 file_operations、open、IRQ/GPIO、AP3216C、UART/SPI 和异步通知。

答 1｜设备如何匹配，应用如何访问？ I²C 控制器注册适配器；设备树子节点描述地址、compatible 与硬件资源；创建 I²C 设备，匹配后调用 probe。probe 完成资源获取和初始化，再注册合适的子系统。字符设备把设备号与 cdev、file_operations 关联，用户态通过 /dev 调用 open/read；而触摸驱动通常经 input/evdev 暴露，不需要每个驱动自己创建设备节点。

答 2｜I²C 读寄存器与排错。 常见过程是 START、写地址和寄存器号、重复 START、读地址、读数据、STOP；主机读最后一字节通常回 NACK。地址无应答先看供电、复位、pinctrl、总线号和 7 位地址，再抓波形。AP3216C 是否已有合适驱动要看实际内核树、配置和 binding，别凭印象断言。UART 是异步串行，SPI 是时钟同步，I²C 用共享开漏总线和地址区分设备。

答 3｜GPIO 和 IRQ 为什么不能混？ GPIO 极性和 IRQ 边沿／电平触发是两套配置。可用资源直接获取 IRQ，或按实际硬件映射 GPIO。可用运行中的设备树和 /proc/interrupts 对照验证。用户态异步等待可用 poll/epoll；fasync 若启用可发 SIGIO，通知不等于数据本身。

实习面经 · RTOS 与传感器

逐际动力实习：RTOS、时钟域与传感器

原帖题目要点： RT-Thread 任务优先级、FPGA 跨时钟域、温漂、陀螺仪与里程计融合。

答 1｜优先级和跨时钟域。 优先级看截止期、阻塞和负载；关键任务保持短小，长时间持锁会增加阻塞。普通单比特、足够稳定的信号可用两级同步器降低亚稳态风险；窄脉冲用握手或脉冲同步，多位连续数据用握手或异步 FIFO，不能逐位同步就认为数据一致。

答 2｜温漂与融合。 先统一时间、坐标和单位，用静止段估陀螺零偏，有条件做温度标定。陀螺作短时预测，里程计作约束，检测打滑后降低其权重；用可重复轨迹评价误差和漂移。没做过融合，可以用自己做过的时间戳关联说明可迁移能力。

实习面经 · 项目与通信

网易实习：UART 带宽、IPC 和 FreeRTOS

原帖题目要点： 电机调试、串口吞吐、CAN 帧与 CRC、Linux BSP 与 IPC、FreeRTOS 调度和队列、DMA、ROS。

答 1｜115200 波特率每毫秒传几字节？ 8N1 下每个数据字节对应 1 起始位、8 数据位、1 停止位；理论 115200 / 10 = 11520 字节/秒，即 11.52 字节/毫秒，未扣除间隔与协议开销。CAN 还要算帧头、CRC、位填充和帧间隔，不能直接把总线比特率等同载荷速率。

答 2｜IPC 与队列怎么选？ 小消息可选管道或 Unix 域套接字；大数据可选共享内存，但需要另设计同步和所有权。FreeRTOS 队列适合传小消息和做阻塞通信；ISR 用 FromISR 系列，是否请求切换看是否唤醒更高优先级任务以及移植层。典型 Cortex-M 移植用 PendSV 完成切换，不代表所有架构都这样。

实习面经 · 音视频

影石实习一面约 45 分钟：音视频、网络与存储

原帖题目要点： WebSocket 会不会重发、TLS、TCP/UDP；NV12 和 YUV420；Opus 包时长和压缩率、与 AAC 的区别；MPP/H.264 的 GOP、帧间与帧内预测、SPS/PPS、RTP 的 FU-A；线程创建、互斥锁／自旋锁／读写锁、trylock；write 是否落盘、虚拟内存的大地址空间和 static 链接性。

答 1｜WebSocket 断线了会自动补发吗？ 活着的连接中，TCP 重传丢失的字节并保持有序，不等于对端应用已经处理。重连是新连接，WebSocket 不会自动补上上一条连接中未确认的业务数据。若设计补传，用稳定事件 ID 或序号、持久化待发送队列和应用层确认，接收端去重。断线本地录制与重连同步可作为独立能力验证。UDP 不保证到达、有序或重传；常见 TLS 1.3 证书握手协商密钥并认证对端，之后用对称密钥保护记录。WebSocket RFC

答 2｜怎样解释 H.264 分段和传输？ 帧内预测用当前图像信息，帧间预测用参考图像；并非每个 I 帧都能作独立随机访问点，优先用编码器标记的可随机访问点（例如 IDR），并确保段能取得正确的 SPS/PPS 或容器配置。讨论具体方案时说明分辨率、帧率和分段时长的约束。GOP 影响起播、寻址与码率；码控方式、目标码率、帧率和 profile 是常见配置维度，不说自己都调过。RTP 中能放进 MTU 的 NAL 可单包发送，多个小 NAL 可聚合（模式允许时），过大则分片或让编码器控制切片大小；WebSocket 同步与 RTP 传输不是一回事。H.264 RTP RFC

答 3｜如何区分 Opus、AAC 和 NV12？ Opus/AAC 是音频编解码方案，压缩率取决于输入 PCM 参数及实际码率，包时长看配置和封包方式，不是固定常数。可用 PCM 码率（采样率 × 位深 × 声道）除以编码码率作估算；WAV 中的 PCM 与 Opus 压缩数据不是一回事。NV12 则是图像像素格式，见下文传音答法。

答 4｜并发与持久化怎么解释？ pthread_create/std::thread 创建执行流；用 mutex 保护共享状态、条件变量带谓词等待。trylock 加释放重试仍可能活锁或饥饿，先考虑固定锁顺序；自旋仅用于适合短等待的场景。普通文件 write 返回成功通常只表示数据被内核接受；要按持久化要求检查 fsync 返回值，原子改名后的目录持久性也需考虑同步目录。申请大虚拟地址范围与实际触页、物理存储及配额是两件事。文件作用域 static 的关键是内部链接，不是把对象放在哪里。Linux fsync

实习面经 · 驱动与 BSP

高通暑期实习：设备树、Kbuild 与相机缓冲区

原帖 23 项题目要点（按主题转述，括号为原帖编号）

字符设备与启动（1–4）： 字符设备从注册到应用访问怎么接通；初始化入口如何执行；内核启动回调有什么用、为何分层。

匹配与构建（5–10）： 平台设备如何通过设备树绑定、匹配先后如何判断；不走默认匹配能否自行识别；自定义设备树属性能否读取；如何编译为模块或内建，两个 Kbuild 目标分别起什么作用。

相机与缓冲（11–15）： 相机驱动做过什么、具体改了哪里；怎样分配和使用视频帧内存；缓冲区有哪些约束、如何建立缓冲池并在各环节间交接。

中断、锁与项目（16–18）： 中断与其他执行上下文如何同步；两种常见内核锁怎么选；如何介绍自己的项目。

算法与操作系统（19–23）： 判断两条链表是否共用节点；哈希表如何工作；结合项目解释何时发生任务切换；调度怎样选下一个任务；堆与栈怎么区分。原帖第 6、16、21 项写得简略，下面是练习方向，不是现场问法的还原。

答 1｜怎么把字符设备接到应用？ 分配设备号，以 cdev_init/cdev_add 把设备号和 file_operations 关联；需要标准设备节点时再注册 class/device，由 devtmpfs 等机制建立节点，具体取决于板端配置。应用打开节点后，VFS 按设备号找到字符设备并分派 open/read/write/ioctl。初始化按依赖顺序做，失败按反序回收；卸载时考虑仍打开的文件和异步回调，不要让它们继续访问已释放的资源。V4L2 或 input 等已有子系统的设备优先走对应子系统，不是所有驱动都自己创建字符设备。

答 2｜module_init 和 initcall 有何关系？ 内建时，module_init(fn) 把入口登记到启动 initcall，启动时按层级执行；作为模块时，模块加载成功走到初始化阶段才调用该入口，不参加启动的 initcall 排序。分级是为了让基础设施早于依赖它的子系统和驱动；不能仅靠同一层级的链接顺序表达硬件供应者依赖。若时钟或 regulator 等资源尚未就绪，按框架传播 -EPROBE_DEFER，不要自行忙等。Linux 驱动入口文档

答 3｜设备树如何匹配？自定义属性能做什么？ 对已枚举到 platform bus 的设备，常见主线实现先看显式 driver override，再尝试 OF、ACPI、平台 ID 表，最后才可能按名字回退；有 ID 表时，未匹配不会继续用名字兜底。OF 常用节点 compatible 对应驱动的 of_match_table，匹配成功后才能进入 probe。已有 platform 驱动不能靠添一个任意属性替换总线的匹配函数；可在 probe 中按 binding 用 device_property_read_* 读取自定义属性做配置或校验。若真要自定义匹配机制，那是另一个 bus 的设计问题。外设若挂在 I²C 总线上，应按相应的总线匹配流程讲解。平台驱动文档

答 4｜怎么做成 .ko 或内建？ obj-$(CONFIG_FOO) += foo.o 对应 Kconfig 的 tristate：y 进入内建目标并最终链接进内核，m（启用模块支持时）产出可加载模块，未启用则跳过；obj-y 和 obj-m 分别直接选择两条构建路径。多源文件可用 foo-y := core.o bus.o 组成同一个目标。排查时分别确认配置是否生效、父目录是否递归进入、产物与目标内核是否匹配，板端再用启动／加载日志及设备绑定情况验证。只描述你实际修改过的 Kconfig、Makefile 或 DTS。Linux Kbuild 文档

答 5｜相机做过什么，帧缓冲怎样流转？ 先画 sensor → CSI/ISP → capture → 编码／应用，把自己负责的层和改动证据标清，不把使用 V4L2 写成开发 sensor 驱动。以 V4L2 MMAP 为例，协商格式后 REQBUFS 建池，QUERYBUF 获取映射信息，映射后 QBUF 交给驱动、STREAMON 启动；DQBUF 后用户才取用该帧，消费者用完再送回。检查 plane、stride、sizeimage、设备可寻址范围和映射条件；是否要求物理连续取决于设备、分配器及 IOMMU，不是一律连续。跨设备能用 DMA-BUF 时，还必须约定所有权、同步及回收时机，传 fd 不等于自动无拷贝或没有竞态。V4L2 MMAP · DMA-BUF

答 6｜中断和线程如何同步？ 先区分硬中断、线程化中断／工作队列和普通进程上下文。硬中断做必要的状态确认和通知，不调用会睡眠的接口；耗时或可睡眠的处理移到适合的上下文。常规非 RT 内核里，若进程与同 CPU 的硬中断都访问同一状态，进程侧可用 spin_lock_irqsave 并保持临界区短；只在可睡眠上下文操作的共享状态可用 mutex。等待单次操作完成可考虑 completion：等待端在可睡眠上下文，完成端发通知。PREEMPT_RT 下锁语义要以对应内核为准。内核锁规则

答 7｜链表相交、哈希表、堆和栈。 无环单链表按节点地址判断交点，不按值；双指针各走完自己的链表后切到另一头，走过相同总长度，会在交点或空指针相遇，时间 O(n+m)、额外空间 O(1)。题目允许环时先确认边界，不能照搬。哈希表用哈希定位桶，冲突可用拉链或开放寻址，平均代价受负载因子和分布影响，最坏可退化。栈常存自动变量和调用帧，实际寄存器分配遵循编译器和 ABI；动态存储由分配器管理，生命周期由显式释放或资源所有权控制，不由退出作用域直接决定（RAII 对象可在出作用域时负责释放资源）。

答 8｜项目介绍与任务切换。 用「负责哪段 → 为什么会卡住 → 用什么观测定位 → 怎么验证」讲自己的相机流水线；例如准备解释写盘变慢时哪个线程阻塞、队列如何增长，但不要把设计设想当实测。系统层面，阻塞等待或抢占可触发调度，唤醒只代表变为可运行，不保证当场切换；系统调用或中断进入内核也不等于切换到另一任务。先说明调度类：普通公平类按目标内核版本解释 CFS 或 EEVDF，实时类按所用策略与优先级解释，不要统一答「时间片用完就切换」。若要证明项目中何时切换，可用 sched_switch、唤醒事件和关键时间戳对齐。EEVDF 调度文档

字节 C++ 日常实习一面：xv6 项目追问

原帖题目要点： xv6 如何分配物理页、惰性分配有什么代价、COW 如何实现、定时器回调、虚拟地址宽度和有没有 swap。另问 TCP 状态机与快重传、音频重采样项目与前 K 高频；二面另问网络中断、拥塞场景和有序整数压缩。此处重点复习 xv6。

答 1｜物理页如何分配？ 基础 xv6 的 kalloc/kfree 管理空闲物理页，初始是受锁保护的一条空闲链表；给进程使用时，由虚拟内存代码建立映射。这不是 Linux 的 vmalloc。MIT 锁实验中的优化思路是：每 CPU 一条链表和锁，优先取本地页，本地为空时从其他 CPU 转移一批；读取当前 CPU 和访问本地队列要防止迁移或抢占引发错误。用相同核数和负载比较 kalloctest 的争用计数，并用 usertests 查回归。MIT 锁实验

答 2｜惰性分配和 COW 有何不同？ 惰性分配让 sbrk 增长合法堆范围，首次访问缺页时再分配、清零并映射。省去未访问页，但首次访问要付陷入成本；故障地址越界、触到保护页或内存不足不能当成普通缺页。COW 则在 fork 时共享已有物理页，对原本可写的映射取消写权限并标记 COW；写故障后才复制并改映射，原本只读的页不能变可写，最后一个引用释放时才回收原页。MIT 惰性分配 · MIT COW

答 3｜Sv39 与定时器怎么讲？ Sv39 是 39 位虚拟地址：三级各 9 位索引、12 位页内偏移，不能由虚拟位宽反推物理内存容量。课程版 xv6 的可用虚拟地址范围和 QEMU 物理内存配置要按你的版本核对，别把它当成支持 swap。若问用户态 alarm，可讲时钟中断达到条件后保存现场、把用户返回地址指向回调、用 sigreturn 恢复，并阻止重入；区分课程原版和自行补充的功能。

自练追问｜为什么 copyout 也要处理 COW？ 内核经地址翻译后直接写物理映射，不一定走用户态 PTE 写权限触发的 fault。若直接写共享页，会让父子进程互相看到本不该共享的修改。写入前走同一套 COW 拆分逻辑，并逐页检查跨页写；可用 read 等会向用户缓冲区写入的系统调用验证隔离。

自练追问｜分桶 buffer cache 如何保证同块只有一份？ 命中时在目标桶锁内找并增加引用；未命中时将「再次查找目标 → 选择未被引用的缓冲区 → 重新标记并插入」做成一个对并发 miss 可见的原子过程，例如有序持锁或用单独的 miss 锁串行化后重查。否则两个线程可能都认为没缓存而分别插入。桶锁保护索引和引用，缓冲区自己的睡眠锁保护数据；不要持自旋锁等待持久化 I/O。用同一块并发读写和频繁驱逐压测，再跑对应的 bcachetest 与 usertests。

答 1｜有没有移植过 LVGL？： 先分清 Application Integration（应用集成）与 Porting（移植）。假如只在现成的显示后端上做过界面，就先讲实际改了哪一层，而不是说从零写了驱动。如果让我从头接，先跑通 Tick（时基）和 lv_timer_handler()；再注册 Display（显示设备），配好分辨率、像素格式、Stride（行跨度）和 Draw Buffer（绘制缓冲区）。先用纯色和色条查黑屏、花屏、颜色顺序，再接触摸并验证坐标。异步 DMA（直接内存访问）还在读缓冲时不能提前调用 lv_display_flush_ready()；它表示缓冲可以再用，不等于屏幕已经显示。这里用的是 LVGL 9 接口。

答 2｜项目和 PR 怎么讲？： 用“我负责哪一层 → 遇到什么问题 → 我改了哪里 → 怎么验证”讲，别先报代码行数。例：回放进度条可以在拖动时只改 UI，松手才提交 Seek（跳转），避免给后台连续发定位请求。后台线程把结果通过 Queue（队列）交回 UI 线程更新控件；Qt 可以用 Queued Connection（队列连接）让槽在接收对象的线程执行。真有上游 PR 再讲对应 diff、复现和验证；没有就讲自己的应用改动。

答 3｜C 内存、指针和编译怎么答？： 数组是连续元素，指针是地址值；数组表达式通常会转换为首元素指针，但对实际数组用 sizeof 仍是整个数组大小。typedef 是类型别名，宏先做预处理文本替换；struct 成员各自有存储并可能有填充，union 共享存储。Wild Pointer（野指针）通常指未初始化等无效指针，Dangling Pointer（悬空指针）指目标寿命已结束。把一个指针置空不能修复别名，先讲 Ownership（所有权），C++ 可用 RAII。常见布局说清代码、只读数据、已初始化数据和 BSS，再区分调用栈与动态分配；别背固定地址。编译按预处理、编译、汇编、链接展开。

答 4｜Linux、RTOS、通信怎么答？： 进程一般有独立地址空间，同进程线程共享地址空间但有自己的栈和调度状态。管道适合字节流，共享内存还要同步，Socket（套接字）可用于进程间或跨机器通信。Linux 调度按 runnable（可运行）状态和调度策略解释，别把 Cortex-M 的 PendSV 当 Linux 通用机制。比较 RTOS（实时操作系统）时先说具体版本，再比优先级、抢占、同步和资源开销。TCP 是可靠字节流协议，不与串口电气规范在同一层；RS-232 单端，RS-422/485 差分，选型看驱动器和接收节点拓扑、双工、距离与终端。

答 5｜音视频及外设怎么答？： H.264 可从帧内／帧间预测讲到 NAL Unit（网络抽象层单元）与 SPS/PPS（序列／图像参数集），再区分编码和封装。H.265 换了编码结构，通常在相似画质时可降低码率，实际取舍还看端侧硬件和编码设置。外设按场景答：I²C 用于寻址和寄存器配置，SPI 是同步串行，UART 是异步串行，ADC 把模拟量变成数字量，CAN 涉及仲裁和错误处理，DMA 是数据搬运机制而不是通信协议。挑实际用过的一项说明怎么验证。

答 6｜Bootloader 体积和低功耗怎么答？： 先用 Linker Map（链接映射）和段大小查占用，再考虑去掉未用功能、日志和库，按实际存储镜像量化，回归启动及回退。低功耗先量静态电流和唤醒周期，再拆不必要的外设时钟、唤醒源、唤醒耗时和漏电路径；用相同工况比平均电流和响应时间。没做过就说是定位方案，不把别人的 MCU 优化说成自己的。

自练追问｜显示卡顿怎么定位？： 作者说准备的 LVGL 渲染管线没有被问到。自己练时可区分 Frame Produced（帧已生成）、Flush Done（缓冲可复用）和 Visible Output（屏幕实际可见）。用同一段输入分别记录各阶段的间隔；看到刷新回调次数变多，不等于 LCD 出现更多不同画面。

字节 AI 芯片 BSP 验证暑期实习一面：相机驱动与 V4L2 mmap

原帖题目要点： 原帖问了相机驱动框架、驱动开发中本人做过什么、V4L2 里 mmap 的用途、研究生课程、应用层更常用 C 还是 C++、C++ 的 struct 与 class、static 的含义，以及手写把二叉树原地展开成链表。作者赛前复习 PCIe，但没有把它列为本轮考题。

答 1｜相机驱动框架怎么讲？ 我会分 Control Path（控制通路）和 Data Path（数据通路）。以一条常见链路为例：I²C 配传感器模式，像素走 MIPI CSI-2 到接收器，再经过采集或 ISP（图像信号处理器）；具体有没有 ISP 看硬件。Media Controller（媒体控制器）描述实体、端口和连接，传感器通常是 V4L2 Sub-device（子设备），抓帧应用通常从 /dev/videoX 操作 Video Node（视频节点）。先用 media-ctl 看拓扑，再看各级格式是否衔接和首帧有没有回来。I²C 有应答，不代表数据通路有帧。

答 2｜V4L2 mmap 有什么用？什么时候能把缓冲区还回去？ mmap（内存映射）是把驱动分配的采集缓冲区映射到用户进程，不是每帧通过 read() 再拷一份。申请和查询用 REQBUFS、QUERYBUF，按 offset 和 length 映射；先 QBUF 入队再 STREAMON，DQBUF 后用户读，读完才 QBUF 还给驱动。映射还在也不代表你一直拥有缓冲；异步编码器还在读时就归还，驱动可能把下一帧写进去。要么等消费者结束，要么复制到自己管理的缓冲再归还。这里避免的是这一步的复制，不代表端到端 Zero Copy（零拷贝），也不自动等于 DMA-BUF 共享。

答 3｜C/C++、struct/class 和 static 怎么答？ 先按自己实际负责的模块回答用 C 还是 C++，不要编比例。C++ 的 struct 和 class 都能有构造函数和虚函数，主要语言区别是默认成员访问权限和默认继承权限：struct 默认 public，class 默认 private。static 分开说：C 文件作用域的函数或对象是 Internal Linkage（内部链接），块内 static 对象具有 Static Storage Duration（静态存储期），跨调用保留状态；C++ 类的静态成员不属于某个实例，静态成员函数没有 this。项目和课程追问各举一个真例，说明做了什么、怎么验证。

答 4｜二叉树怎么展开成链表？ 按 Preorder（先序遍历）保留根、左、右的顺序。先写简单方案：显式栈先压右再压左，弹出节点后把 prev.right 指向它，清空 prev.left。扫描一遍是 O(n)，栈最坏 O(h)，最后把尾节点左右置空。追问 O(1) 额外空间时，对每个有左子树的当前节点，先把原右子树接到左子树的最右节点，再把左子树搬到右指针，并清空左指针，沿右指针往前走。用空树、纯左链和左右皆有的树验证。

面试前先练这三件事

讲一个项目，90 秒。 用「问题 → 自己负责的部分 → 一个难点及证据 → 验证结果」讲。只报亲自测过的数字；没测就说准备怎么测。

画一条 Linux 驱动链。 从设备树匹配和 probe 讲到驱动注册、设备节点、应用 open/read。准备解释在哪看日志，怎么区分未匹配和通信失败。

演练一次故障定位。 选 I²C 无应答、串口丢帧或传感器时间戳不同步之一，讲清复现、观察、排除、改动、回归五步，再补一个你能讲清取舍的同步机制。
